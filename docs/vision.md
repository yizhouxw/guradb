# GuraDB 产品定位与范围

**2026-10-30现状与执行基线：** 完整定位不变，当前只有单机Rust CLI及有界真实图片描述检索。旧在线/索引/湖/训练/worker实物已退役，不能计当前完成度；原历史证据保留。最新阶段顺序和出口见[路线图](roadmap.md)，近期队列及全部需求映射见[新交付计划](plans/2026-10-30-delivery-path.md)。

状态：产品需求基线；已有有界 alpha，但完整数据库目标未交付。纠偏日期：2026-10-19。

本轮[产品交付合同](product/product-contract.md)将完整对象、六条用户旅程与验收补到主线；[方向复审](reviews/2026-10-19-product-direction.md)说明工程切片如何偏离产品交付。项目不能被缩为湖文件查询模块或检索作业集合。

## 1. 产品定位

GuraDB 是面向 AI 训练、推理与 AI 应用的分布式多模态湖数据库，以对象存储和开放数据生态为基础，提供数据准备、可复现训练数据集、关系分析以及全文/向量/Graph 组合检索。

“一体化”首先体现为共同的数据身份、版本、权限、处理血缘、查询计划和发布语义；不同模态和检索方式可以使用不同物理布局与索引。详见[产品功能架构](product/functional-architecture.md)与[调研结论](research/README.md)。

首个产品样板按2026-10-20[评审决定](decisions/0020-product-review-and-vertical-delivery.md)聚焦企业图文知识库、带版本证据检索及同语料embedding/reranker训练评估。共同身份/版本/权限能否降低应用同步和追溯成本，需要同质量对照与用户试用证明；首批语言/模型/样本及预算先冻结。音视频、分布式等长期目标保留，不把首片边界升级为永久限制。

## 2. 用户已确定的方向

| 方向 | 产品要求 | 需要继续细化的边界 |
| --- | --- | --- |
| AI 全生命周期 | 面向训练、推理和 AI 应用 | 首批工作负载与部署预算 |
| 多模态 | 存储、管理与检索文本、图像、音频、视频及派生数据 | 模态片段坐标、对齐和处理能力 |
| 多种检索 | 全文、向量、Graph 与关系查询 | 组合语义、精度与资源预算 |
| 海量数据 | 分布式、水平扩展 | 规模、容错与恢复指标 |
| 对象存储湖架构 | 业务持久数据以对象存储为基础 | 后端语义认证、缓存、布局与成本 |
| 负载取舍 | 放弃高并发 OLTP，不支持实时延迟敏感事务 | 批量写入、数据发布及索引就绪的时间目标 |
| 开放湖生态 | 持续覆盖主流与 AI 多模态相关格式 | 版本、只读/导入/导出/写回能力矩阵 |
| 湖加工结果服务化 | 将源版本、数据接入/物化与所需索引共同发布为可查询视图 | Snapshot、显式触发增量、后续 Continuous，以及独立可观察的同步进度 |
| PostgreSQL 语法 | PG 兼容方向，提供 SQL 与 HTTP | 具体 SQL/类型/函数子集及客户端范围 |
| Agent 使用 | 方便扩展 CLI 与 MCP | 发现、结构化输出、长任务和权限 |

新增负载边界由 [ADR 0002](decisions/0002-object-store-lake-boundary.md)记录。不做业务 OLTP 不会取消快照原子发布、持久提交、冲突检测或小型控制面的一致性要求。

## 3. 本轮选择的产品流程

| 场景 | 代表流程 | 验证目标 |
| --- | --- | --- |
| 多模态 RAG / Agent | 过滤 → 全文/向量召回 → 关系扩展 → 融合/重排 → 原文/片段证据 | 统一版本、权限和来源，近似结果可解释 |
| 训练数据集 | 选择样本 → 关联标签/模态 → 固定 revision → split/manifest → 并行读取/导出 | 样本和模态对齐、版本可 pin、重复读取与恢复可复现 |
| 推理数据读取 | 按实体关联特征、检索上下文和媒体片段 | 明确新鲜度和预算，避免无预算原始对象下载 |
| 增量数据维护 | 批量导入 → 数据提交 → 异步索引 → read view 发布 | 数据提交与索引可检索分开，失败不产生半个发布 |
| 湖加工结果同步 | 上游提交 → 固定源版本 → 快照/增量接入 → 索引维护 → 共同发布 | 不漏加载期间变化，不混用源版本，写入权威与同步进度明确 |

这些流程是产品目标，不是第一个 alpha 的共同前置条件。P0 由多个可验收切片组成，包含分布式、多种检索和湖同步；单节点 alpha、完整 P0 与可发布产品分别验收。范围、依赖及退出条件统一以[路线图](roadmap.md)为准：从当前固定文件读取与图片描述查询起步，先补准确证据、排名/精确混合检索和同语料实际消费，再扩湖Snapshot、ANN、Graph、受限增量/托管append，最后验真实分布式和生产发布。

P0 提供批量和显式小批作业，首条湖增量限于路线图指定的 Iceberg append-only 子集。未覆盖的更新、删除、rewrite 或回滚须明确拒绝，或按已配置、可观察的策略 Snapshot 重建；不静默漏读，也不绕过 reader 的特性白名单。持续微批、自动处理回填与批式 UPDATE/DELETE/MERGE 为 P1。推理指模型周边的数据检索，不将 GPU 模型 serving、训练调度或实时事务特征服务纳入首版。

湖同步保留 Snapshot、显式触发增量与后续 Continuous 的方向。同步表示只由其权威源维护，应用写入使用独立数据集。完整目标见[湖加工结果同步与服务化](product/lake-sync-and-serving.md)及 [ADR 0006](decisions/0006-lake-sync-and-serving.md)。

## 4. 产品原则

1. 同一逻辑 ID 与明确版本连接资产、片段、特征和关系，压缩/重排不能改变业务身份；稳定键、无键源与记录版本的能力边界统一遵守[数据契约](product/data-contracts.md)。
2. 数据有明确权威来源；开放事实层与检索物化层单向关联，不同步维护两套主表。
3. 默认查询固定已发布 read view，数据提交与索引就绪分开，滞后可见，完整性不能静默降级。
4. 训练/扫描、交互检索和后台构建独立管理预算、调度与缓存影响。
5. SQL/HTTP/CLI/MCP 使用相同权限、版本、错误、预算与取消语义。
6. 兼容逐版本、逐功能验证；不支持的行为明确拒绝，不解析后忽略。
7. 冷热对象 I/O、召回、构建、存储放大和恢复成本与 QPS 同等重要。

## 5. 推荐技术基线与非目标

本轮推荐 Iceberg v2/Parquet 事实表、外置媒体对象、Lance 派生物化、Rust/Arrow/DataFusion 执行、Tantivy/邻接访问结构与 PostgreSQL 小型控制面。组件按里程碑接入：最小固定文件读取无需全部依赖同时到位；Lance 先服务内部 ANN 切片，外部 Lance 连接器另行验收。具体选择和可推翻条件见 [ADR 0003](decisions/0003-storage-and-execution-baseline.md)，发布不变量见 [ADR 0004](decisions/0004-snapshot-and-index-publication.md)。

PostgreSQL 18 为 SQL/类型比较基线，按子集验收；客户端直连通过独立 [PG wire 切片](design/pg-wire-running.md) 推进，首片针对本机 psql/Psycopg 的只读 autocommit，不由语法兼容推导全部驱动、事务或扩展兼容。全文 PostgreSQL 表面与 Tantivy 语义不能按同名推定，向量/Graph 最终 SQL 扩展另行细化。

首版不承担高并发 OLTP、交互式多语句业务事务、行锁/触发器、强制跨湖唯一/外键约束、PG 扩展 ABI、跨外部湖全局事务、完整 Cypher/GQL、无界图算法、模型 serving 与训练平台调度。

湖覆盖是长期生态目标，不要求所有格式同一套读写能力。注册、直接扫描、导入、导出和原地写回分别认证；媒体保真存储、外部片段/特征接入与内建 codec 解码也分别认证。外部 Lance/WebDataset、复杂训练导出和内建多媒体处理按后续需求开启，长期格式目标及认证维度见[兼容矩阵](compatibility/lake-formats.md)。

## 6. 成功标准的待填写项

| 维度 | 测量内容 |
| --- | --- |
| 正确性 | SQL 子集结果、跨模态对齐、删除/快照、来源、权限与故障后状态 |
| 数据规模 | 资产/片段/边/向量数量、维度、原始大小、分布与增长 |
| 检索 | recall/相关性、并发、冷热 p50/p95/p99、新鲜度与图预算 |
| 训练 | 扫描/样本吞吐、随机/混洗成本、worker 划分、恢复与版本保留 |
| 分布式 | 多 worker 归并、故障/重试、扩容、重平衡和恢复目标 |
| 成本 | 存储放大、构建时间、对象请求/字节、缓存、网络与资源干扰 |
| 兼容 | 固定 PG 用例、格式版本/特性、外部工具互操作与限制清单 |

没有足够工作负载依据时不承诺性能数字；测试前先冻结目标和预算，避免测试后选择有利指标。

## 7. 下一步

按2026-10-30新路线收口在途图片级结果，然后交付准确媒体证据读取、BM25排名、外部特征的精确向量/融合、同语料样本实际消费与可反复更新的单机预览。之后扩展对象存储/湖Snapshot、托管导入/增量、SQL关联聚合、ANN/Graph、音视频、共同入口与治理，再验真实多机和生产发布。

共同身份/版本/权限与恢复仍是完整目标；按新风险实际引入，不要求先建通用多租户、PG控制面或pin平台才能跑首条可信单用户用例。详细依赖/退出条件以[路线图](roadmap.md)为准；本次文档重排没有新增运行时能力，不认证性能/规模或生产就绪。
