# 实施路线：从当前 Rust alpha 到完整多模态湖数据库

2026-10-30 重定。本文为当前实施顺序与阶段出口的唯一产品入口，替代此前按旧模块现状安排的任务顺序。
完整目标保留[产品合同](product/product-contract.md)的六条旅程、[功能架构](product/functional-architecture.md)的十二能力域；
[执行计划与42项需求映射](plans/2026-10-30-delivery-path.md)负责近期队列与缺口。
旧版本路线/实验记录留在Git与原报告中，不改写历史通过或失败，也不据此恢复已退役服务。

## 1. 起点：哪些已经交付

基点main `f63606038c94d98b996b6329c4e7d3b8b5c388be`（[PR230](https://github.com/yizhouxw/guradb/pull/230)）。
可信单用户、单本地固定Parquet、单Rust CLI；Int64/Utf8/Boolean、投影/比较/布尔/NULL/排序/LIMIT、受限case-sensitive LIKE。
真实三图/15条caption已关联并实际解码，关键词可区分厨房/街道/浴室；正常本机门禁、非作者与精确main证据已交付。
当前是 **core-limited**：不是完整M0/M1、单机完整产品、全文排名、视觉/语义检索或生产发布。

图片级 `DISTINCT` 正在独立任务中实施，未合入并完成精确main验收前不计已支持。
后续状态以[当前用户手册](user/simple-alpha.md)与版本化能力声明为准；本页规划不授予运行时能力。

旧Python在线、HTTP/PG、BM25/向量/Graph、湖连接器、训练和worker实现已经按[清单](../harness/alpha-retired.json)退役。
旧源码/旧M0–M4报告只提供经验，不能折算为当前完成比例。六条完整旅程均尚未完成；当前仅J2/J3的有界子集。

## 2. 完整目标与分阶段约束

最终交付仍是面向AI应用和训练的分布式多模态湖数据库：对象存储与开放格式、共同数据身份/版本/权限、
SQL分析、全文/向量/Graph组合检索、同语料训练选择与消费、更新同步、分布式运行和可恢复发布。
不做高并发OLTP、模型serving、训练调度平台、跨湖全局事务或无界图计算。

继续使用M0–M4表示“底座→单机价值→完整能力→分布式P0→生产”的验收层级；以下重排其建设顺序，
旧M0中的S3/HTTP和旧M1中的PG控制面等义务移入实际需要它们的阶段，绝不因未进首片而删除。
多租户、通用版本、pin/lease/GC、分布式平台不成为当前单用户第一条用例的前置。
相应风险一旦由共享服务、更新、训练保留或远程访问引入，就必须在该能力宣称可用前验收。

## 3. M0：收口当前单机底座

已交付读取、进程资源边界和真实caption过滤。当前只收口在途图片级唯一结果及其手册/拒绝边界，
随后停止以增加固定样例、SQL小修或测试数量替代产品主线。

出口：现有CLI可返回准确、唯一的图片ID/定位，原caption明细不变；排序/LIMIT/NULL、失败与进程终态有独立证据。
它仍只是新路线的底座，不回填旧M0完整通过。

## 4. M1：可使用的单机图文知识检索闭环（下一主线）

按消费者结果推进，继续一个Rust在线执行权威，Python只做离线准备、客户端及工程验证。
不先建全套目录/权限/服务平台；CLI先贯通，HTTP/PG属于后续共同语义适配。

| 顺序 | 可观察交付 | 必要依赖与退出条件 |
| --- | --- | --- |
| M1.1 准确证据读取 | 从命中结果取得确切版本的图片/文本字节，而不只返回路径 | 最小输入描述绑定源Parquet与asset ID、相对定位、摘要/大小；Rust有界读取。缺失、替换、错关联、越界/超限明确失败；同一查询证据不混源。先一种本地布局，不造通用目录 |
| M1.2 有排名的文本检索 | 用户换查询能得到BM25排名、命中原文/片段、图片证据 | 一份可复现本地图文语料与最小导入合同，稳定ID/字段映射；固定分析器/语言、分数与同分排序。先精确算法真值，再冻结查询/人工标签评估相关性；LIKE仅作对照，不冒全文 |
| M1.3 精确图文向量与融合 | 一种固定模型空间的精确Top-K，与文本/过滤融合，返回相同证据 | 离线外部特征、明确模型/维数/距离/输入身份；独立数值真值、错模型/维数/NaN/Inf拒绝，候选预算与RRF/同分规则可解释。不先做ANN或在线模型推理 |
| M1.4 同语料样本消费 | 检索/SQL选择可固定为训练样本，真实reader读取同一图片/文本 | 按asset分组防止多caption跨split泄漏；明确成员、模型、seed/split和源保留责任；独立核集合/字节/尾批与一种固定框架实际消费，不声称模型训练结果复现 |
| M1.5 可反复使用的单机预览 | 用户换受支持数据、完整刷新、安装/诊断/恢复都能按手册操作 | 摆脱硬编码COCO预设；完整不可变输入重建、索引就绪与原子视图切换、重启对账/旧视图可解释。最小持久本地描述即可起步，目录后端按实需决定；CLI与一个薄MCP适配共享Rust语义 |

M1出口：J1/J2/J3/J4/J5/J6在明确单机、单用户、单语料/语言/模型白名单内有一条完整可复制的纵向流程；
包括真实数据、可换查询、准确证据、更新/固定样本消费和干净环境教程，不能靠研发人员修改内部产物完成。
该出口是受限单机预览，不等于六条完整旅程或完整P0。
单机预览的用户价值判断按[产品合同§1](product/product-contract.md#1-用户购买的价值)做同源/同质量组合方案对照，记录接入、同步/追溯、查询/构建/保留成本，不由算法真值推定优势；此对照不阻首个证据读取切片。
COCO用于工程验真，不代表企业知识库需求/中文相关性已验证；中文语料上线前须固定其分析器、模型及人工查询真值。

## 5. M2：开放湖、数据准备及检索能力补齐

建立在M1实际闭环之上，按下列依赖分支推进；不要求等全部模块齐备后才集成。

| 能力分支 | 最小切片与退出条件 |
| --- | --- |
| 对象存储/湖Snapshot | 一种对象后端→有界provider/Range完整性→一个Iceberg/Parquet固定快照子集；独立生态writer互操作，不用LIST猜快照；未知schema/delete/codec/版本拒绝 |
| 托管接入/更新与同步 | 正式批量导入、计数/坏行/重复键、幂等与未知提交对账；先完整刷新/替换，再append-only触发增量；源提交与视图发布分别fence，事实提交与索引就绪可观察；不把rewrite/delete/回滚当append |
| SQL数据准备 | 值参数、受限INNER/LEFT等值JOIN、GROUP BY/COUNT/MIN/MAX逐算子准入；SUM/AVG/decimal和CAST单独冻结精度/溢出合同。为标签/资产/样本关联服务，不追求一次开放全部SQL |
| 索引与混合检索 | 精确向量真值后接一种ANN，固定recall/过滤/回表/构建成本；Graph从同视图typed-edge一跳开始，与ANN可独立推进；融合必须解释候选/排名/截断与路径证据 |
| 多模态扩展 | 图片→音频→视频逐模态接入对象身份、时间/空间片段、派生特征和真实读取；内建OCR/ASR/抽帧按场景单独认证，不由外部caption推定已实现 |
| 训练与生命周期 | 扩展真实批次读取、固定拓扑、多worker/尾批、显式保留/释放；引入共享保留后验pin/GC/撤权，明确上游vacuum边界；不把本地pin说成控制远端保留 |
| 共同入口与治理 | HTTP、MCP、PG wire仅适配同一Rust数据/检索/错误/取消上下文；对外共享服务之前交付最小身份、权限和受控证据读取。PG协议、控制面、物理PG ingest分别验收 |

M2出口：在声明的单机范围内完成上述能力的真实配对及J1–J6集成；安装/能力发现/状态和恢复与功能一起交付。
目标域覆盖F01–F12；ANN/Graph/训练的模块通过不能替代这个产品出口。

### 规模入口与#138

在扩规模前，先消除当前“全文件bytes/全量Arrow/逐请求全量校验”的路径依赖，交付按需扫描、下推、批回表、背压及分片数据布局。
不简单调大32MiB源/32MiB池预算或增加worker。
#138在这些入口和音视频真实读取就绪后执行独立的50–100GB三模态验收：去重原始有效图片/音频/视频字节、
清洗/标注/检索链分别有证据；压缩包、重复副本、synthetic、目录大小和三图样例不计达标。
事实、媒体、向量、索引的规模/缓存关系分别测量；M3再验真实多机成本与容量。
本计划本身不启动大下载、额外费用或新平台权限；对应实施包先冻结可用来源/许可、资源与停止点。

## 6. M3：真实分布式P0集成

以前述单机语义与可分片provider为基线，至少三个真实worker在不同机器承担实际数据/索引工作。
验全局BM25统计、Top-K/RRF、受限关系与训练文件分配，结果与单节点独立真值一致；
验证任务所有权、预算/取消、重试/迟到结果、网络/对象失败、协调器重启和发布恢复。
混合查询、构建/同步、训练消费和容量维护联合运行，分别记录质量、冷热I/O/请求/字节、内存和干扰。
本机三线程/空闲worker不算多机，M3通过也不等于生产发布。

## 7. M4：强化与生产发布

在已集成范围内，补全正式发行安装、版本化配置、权限/审计/观测、备份与联合恢复、升级/回滚、容量与HA演练、
真实性能/故障/长稳、许可证/SBOM/模型与数据分发边界及完整用户手册。
强化/发布的Rust适用100%与Python适用80%覆盖义务、完整源闭包和真实driver继续保留；
不得给已退役Python生产源补虚假分母，也不能把planned/missing改成PASS。
CI/CD与远端准入仍由用户暂停；恢复需另行授权，部署模式各自验收。

## 8. 后续扩展与物理PG研究

Continuous/CDC与批式DML、更多湖格式/reader/writer方向、PG类型/ORM/TLS/目录兼容、
更多语言/分析器/向量模型/量化/Graph路径、训练shuffle/弹性拓扑/续读和细粒度治理，按真实场景从上述主线分支推进。
没有先行证据时保持不支持，不能从同名组件推定兼容。
B01–B05物理PG/Lakebase/Neon目标研究保留为独立探索：先核目标build/版本和原生认领/提交接口；
格式原语或PG wire不能替代目标storage-ingest。接口/授权不可取即记录缺口，不成为当前图文闭环的前置。

## 9. 执行和验收纪律

PM亲自维护目标与优先级，统一development负责技术拆解、非作者、串行集成与回收；源码owner不是人员组织。
同时最多4活跃实例（含PM）、最多2行为作者；独立目标才并行，重资源/main唯一窗口。
每包有消费者结果、原始B、范围/预算/停止点、真值与关键失败、适用门禁/独审/普通PR及精确main证据。
核心阶段先证真实路径/资源模型；纯文档仅文档检查，不重复产品矩阵。无模型/来源/性能预算就先做对应有界POC，不虚构日历或SLO。
每个出口按“已交付/在途/未实现/未认证”报告，不按PR数、源码行数或旧模块数计算产品完成百分比。
