# 路线图与关键 POC

状态：推荐实施路径，尚无数据库实现或运行时测试结果。日期：2026-10-17。里程碑不是日历承诺。

## 1. 范围与验收规则

本文是 **M0–M4 里程碑范围的唯一来源**；功能架构和格式矩阵描述能力域与长期目标，通过引用本页确定实施顺序。P0 是多个可验收切片组成的目标集合，包含分布式、多种检索和湖同步，不等于首个 alpha，也不表示已经支持。P1/P2 按后续需求扩展，不要求在第一个切片同时联编全部依赖。

M0/M1 是内部 alpha 切片；M2 补齐 P0 能力；M3 才验收真实分布式及完整 P0 集成；M4 单独验收生产发布。单节点 alpha、P0 功能完成与可发布状态必须分别报告。

每个切片先冻结输入、支持白名单、功能真值、性能预算和故障断言，再实现和验证；相关 POC 随切片完成，实验代码符合边界后可继续演进，不设完整数据库 POC 的总前置门槛。身份、版本、媒体与授权规则见[数据契约](product/data-contracts.md)。

## 2. M0：固定文件集上的最小可运行读取

### 范围

- Rust/Arrow/DataFusion 最小依赖组合；一个已认证 S3 后端，固定 Parquet 文件 manifest、schema 和不可变对象身份。显式清单来自受控输入，不用目录 LIST 猜测快照。
- 最小目录与固定 read view；实现数据契约中本切片需要的逻辑身份、记录版本与对象引用规则。此时可使用受控持久清单，无需先部署 PostgreSQL 元数据库或 REST Catalog。
- HTTP 参数化只读 SQL：先冻结单表投影、过滤、排序、有界结果及类型白名单；绑定固定视图，返回实际版本。PG18 仅为该白名单的差异测试基线，不承诺完整 PostgreSQL 行为。
- 身份与数据集授权、对象访问控制、超时/扫描/结果/内存预算、取消、查询状态和固定视图分页；最小服务器复用后续接口语义。

### 前置实验与退出条件

依赖联编与固定文件 provider 可运行；用独立 reader 和固定 PG 用例核对结果，覆盖 NULL、参数类型、非法 SQL、超限、取消、缺失/替换对象和未授权访问。未支持的语法、类型及文件特性明确拒绝。

冻结数据来源/种子、规模、硬件、并发、对象区域、冷热定义及预算；记录扫描吞吐、冷热延迟、对象请求/字节和内存。M0 不需要 ANN、Graph、Iceberg writer、PG 控制面或分布式先行完成。退出产物是可复现的小型读取服务及其报告，不能标为分布式数据库或可发布产品。

## 3. M1：首个湖快照服务化与检索/训练闭环

### 依赖与范围

依赖 M0 的固定视图、身份、HTTP 和预算机制，按以下顺序增加能力：

1. 接入第一种外部湖源：Iceberg v2 + Parquet 固定快照读取。冻结 catalog、reader、schema/分区与删除特性白名单；选择一个可验证的定位/catalog 路径，不预设所有 REST Catalog 能力。
2. 引入小型 PostgreSQL 持久控制面，管理数据集、权限、作业、data revision、read view、pin 和发布状态。完成最小 `SyncDefinition`/`SyncRun` 管理及 Snapshot 服务化，明确源湖是写入权威。
3. 注册已由外部生成的文本片段、媒体版本引用、标签和 embedding：使用源 Iceberg 列或不可变 Parquet/对象清单并绑定 read view，无需写托管 Iceberg 业务表。实现 Tantivy BM25、精确向量检索与 RRF，固定分析器/模型空间、候选预算及同分排序；不依赖 M2 writer、Lance ANN 或内建解码/模型处理。
4. 从同一固定视图生成训练 manifest、确定性 split 和 Parquet 导出；记录样本身份、模态对齐、来源及版本保留。HTTP 为必需入口；CLI/MCP 任选一个最薄适配验证 Agent/自动化路径，另一适配可并行推进，完整二者在 M3 集成。

### 前置实验与退出条件

先用独立生态实现生成的 fixture 验证 Iceberg provider，再连接索引和发布。对于尚未实现的 position/equality delete、schema 演进、底层文件或其它必需特性，须在读取前明确拒绝；只有互操作与负向测试通过后才能扩大白名单，不能扫文件后忽略删除。P0 自身暂不提供删除写接口，不影响已承诺源删除语义的正确性要求。

发布必须覆盖固定目标、不可变产物、数据提交与索引就绪分离、目录 CAS、generation/fencing、结果未知对账、重启恢复与旧任务晚完成。先注入单路索引失败及发布边界崩溃，证明旧完整视图保持可用、未完成版本不发布、查询与训练不混快照；同步进度和新鲜度可解释。

退出闭环：注册固定源快照 → Snapshot 扫描/选择性物化 → BM25/精确向量与 RRF → 发布 read view → HTTP 查询及一个薄客户端验证 → 同视图训练 manifest/Parquet 导出。撤权、pin/保留与 GC 竞争、取消和错误路径均需实际测试。M1 仍是单节点 alpha；Graph、ANN、触发增量和分布式尚未完成时不能宣称完整 P0。

## 4. M2：并行补齐 P0 能力切片

下列切片可在 M1 稳定合同上并行推进，各自独立验收，不把未涉及组件设为前置条件。共同要求是不改变权威来源、身份合同与 read view 发布语义。

| 切片 | 依赖 | 最小范围与退出条件 |
| --- | --- | --- |
| M2-V Lance ANN | M1 精确向量真值、固定视图和发布 | 内部派生 Lance dataset/ANN，保存源 ID/记录版本映射；精确重排及过滤；验证删除/compaction 映射、recall、冷热回表、构建与存储放大。内部 Lance 不要求外部 Lance 连接器同时交付 |
| M2-G 受限 Graph | M1 固定关系数据及查询预算 | 先实现带类型边表的一跳 edge join/扩展与路径证据，对照关系真值；明确方向、扇出、边数、时间/内存和截断/超限语义。邻接物化和更多有界跳数按测量增加，不要求首步自建图运行时 |
| M2-S 显式触发增量 | M1 Snapshot、稳定键校验、持久进度与发布恢复 | 首条路径限定 Iceberg 源同一历史链上已验证的 append-only 提交、固定 schema/映射和确定性投影/过滤；人工或上游作业完成后触发；重复/丢失通知不改变源版本真值，四类进度与共同索引发布可观察 |
| M2-W 单表托管 append | M1 持久作业、对象与发布恢复合同 | 一条 Iceberg v2/Parquet 批量/显式小批 append 路径，后台生成不可变文件，经受控入口串行提交单表；独立 reader 互操作，验证提交 fencing、响应丢失后对账和已确认提交不丢；不提供批式 UPDATE/DELETE/MERGE |

M2-S 发现更新、删除、rewrite/压实、回滚/换分支、历史缺口、schema 或键定义变化时，未覆盖情况必须停止并明确失败，或执行事先配置、可观察的 Snapshot 重建；不得静默跳过或仍称 append 增量成功。快照 reader 仍须遵守自身特性白名单；不能以重建绕过未支持的源删除/schema 语义。

源 catalog 提交与 GuraDB 目录发布的 fencing 分别验证，不能认为目录 CAS 已阻止失效 worker 向源生成孤立快照。同步目标沿用 [ADR 0006](decisions/0006-lake-sync-and-serving.md)，Continuous 常驻任务仍为 P1。

每个切片冻结真实工作负载与预算，用热缓存、冷缓存、部分命中及数据大于总缓存的条件记录结果质量和成本。检索/训练与后台刷新并测，不能通过降低 recall、漏读或减少负载声称提速。切片完成不等于分布式 P0 已完成。

## 5. M3：真实分布式与完整 P0 集成

基于已验证的 M0–M2 算子和任务合同，先进行 Ballista/受限运行时的针对性 POC，再接入产品。至少 3 个真实 worker 分担数据/索引分片并进行跨 worker 归并；仅启动 3 个空闲进程或本机线程并行不能验收。

- 完成分片扫描/检索、全局 Top-K/RRF、跨分片受限关系扩展及训练文件任务分配；固定单节点真值和发布视图。
- 统一自定义算子序列化、授权上下文、任务所有权、取消、内存/远程请求预算、spill/背压与错误上报；必要的 exchange 由实际算子驱动。
- query/background 配额与缓存影响可观察；验证 worker 退出、重复 task、旧任务晚完成、网络中断、对象错误、源提交结果未知及发布竞争。
- coordinator 重启与持久作业恢复有明确边界；查询可以明确失败后重试，不能默认所有查询都能透明恢复。通用分布式 JOIN/聚合、复杂训练 exchange 在实际支持前明确拒绝或限于已公布的单 worker 预算。

完整 P0 验收同时运行托管 append、Snapshot/受限触发增量、混合检索/Graph、训练导出与 CLI/MCP，证明不混快照、不重复逻辑发布、不丢已确认提交、超限与失败可诊断，并报告规模、冷热成本、recall 和资源干扰。M3 通过仅表示被测范围内的分布式 P0，不代表已满足生产 release。

## 6. M4：生产发布门槛

在 M3 被测范围上完善并验证发布所需的元数据库 HA/备份与恢复、对象/目录/快照 pin 联合恢复、容量与重平衡、升级/回滚、缓存丢失重建、权限与审计、运维告警、真实长稳及故障恢复目标。任何声称可用的部署模式都需要对应证据，不以单进程测试覆盖 HA。

运行 harness 的 functional/performance/stability/soak 及 release 所有必需门禁，补齐真实 driver 和本次代码/数据/配置匹配的报告；planned/missing 或 bootstrap 通过均不能代替发布验收。依赖许可/词典/codec/模型授权、SBOM、项目许可证及兼容/迁移政策在对外分发前明确。

## 7. 按后续需求开启的扩展

长期目标保留，以下能力不是 M0/M1 或完整 P0 的隐含依赖。新增项目先说明用户负载、依赖、支持白名单与退出条件，再更新本路线图和对应 ADR。

| 路径 | 后续能力 |
| --- | --- |
| 变更与处理 | Continuous 持续微批、更多增量变化子集、批式 UPDATE/DELETE/MERGE、内建 OCR/ASR/embedding、依赖刷新 |
| 湖生态 | 外部 Lance、WebDataset 连接器/导出、Iceberg 更多版本与特性、Delta/Hudi、HF 布局、Zarr/HDF5/LeRobot 等逐版本推进；外部写回独立验证 |
| 多模态 | 已版本化原始对象引用与外部片段/特征继续扩展；内建音视频/文档解码、抽帧、转码和 codec 白名单按需求认证 |
| 查询与客户端 | 更多 PG18 类型/函数/查询、PG wire/驱动矩阵、Arrow IPC file/stream 对外接口、SDK、通用分布式 JOIN/聚合 |
| 检索 | 中文/多语言分析器、更多 ANN/量化、重排、多向量、邻接优化、更复杂有界图与批量图分析 |
| 训练 | WebDataset/领域格式导出、混洗/随机读取、框架适配、训练 checkpoint/epoch、样本去重与成本优化 |
| 治理 | 行列策略、细粒度血缘、成本归因、共享与多集群管理 |

每项“支持”需列版本、方向、特性、互操作测试和限制；外部 reader、内部物化、导出、原地提交不混为一类。所有格式的长期覆盖目标不要求各阶段同时实现所有格式。

## 8. 持续门槛与决策推进

每个里程碑输出支持/拒绝白名单、固定依赖/许可记录、可复现功能/成本/故障报告与未解决风险；只将被测范围内的 ADR 建议推进为实施决定。性能阈值在测试前设定，不在本文填写缺乏依据的 QPS、p99 或 PB 级承诺。

实施过程中始终遵守对象存储湖与非 OLTP 边界，不因后续阶段重新引入高并发 OLTP、实时敏感事务、跨外部湖全局 2PC、完整 PG 扩展 ABI 或无界图遍历。新需求涉及这些边界时，先重评产品与架构约束。
