# 固定视图的正式登记与查询入口

状态：**先行设计，待实现与验收**。本文没有可调用的新 endpoint、DDL、命令或 SDK；HTTP 路径、请求/响应 schema、PG 固定视图适配和错误映射仍须冻结。当前可运行的两条 alpha 路径见[接口说明](../interfaces/query-and-clients.md)，其操作和兼容范围保持原合同。本文不将旧入口升级成共同目录入口。

目标是让同一已授权用户登记受保护的固定数据及索引，再通过 HTTP 或 SQL 查询同一个 dataset/view。登记、目录发布、查询完成分别确认；HTTP 和 PG 只做协议适配，不各自决定数据版本、SQL 类型或权限。本文是实施计划 P08 的 I1 最小切片设计；导入、媒体代理、长期作业、训练消费及完整 G1 仍有后续义务。

## 场景与操作顺序

正式入口上线前，服务必须公布与实际部署一致的协议版本、已启用操作、格式/类型白名单和上限。当前离线[能力清单](../../api/capabilities/v1.json)不等于在线能力发现；具体发现 endpoint 待冻结。未知必需版本或能力应明确拒绝，不能回落到 legacy 或推测支持。

| 用户步骤 | 未来操作及预期 | 当前状态与拒绝边界 |
| --- | --- | --- |
| 确定身份与数据集 | 认证后取得可信租户、主体和委派范围；可信操作者预置数据集及最小权限 | 认证适配待接线；请求体里的身份、管理员标记、授权摘要或 pin 均不能认证调用者。公开建库、DDL、导入和授权管理不在首个查询子片 |
| 登记固定输入 | 提交完整资源/schema、revision、源/对象版本、索引及目标 view 草稿；返回精确 operation 回执 | 须由可信 authority 验证来源、保留与对象/索引能力。当前 P02 的 fixture allowlist 不能作为任意用户数据的认证。不能只交 URI、hash 或“最新”对象 |
| 发布目录 view | 用独立操作和当前权限提交完整目标、预期 generation/旧 view、owner fence 与发布序 | 登记成功不代表已发布。冲突不改写为新 expected 值自动重试；源提交 fencing 与目录发布 fencing 分别验收，首片不写源 |
| 提交查询 | 指定一个 dataset、published 或明确的已发布 view、白名单 SQL、typed 参数与完整预算；服务只绑定一次并返回固定身份 | 查询执行器及真实跨语言接线待交付。不能把准备计划、排队或取得 pin 当查询成功 |
| 查看状态、取结果、取消 | 每次认证并复核当前权限；结果、页或 PG portal 始终属于原主体、query 和 binding；取消可区分请求已收到与实际停止 | 新句柄/游标协议待冻结。未知句柄不重建查询，旧页不改绑最新 view；有 bytes 已交付时不能承诺撤回 |

操作名称描述用户目标，不是 API 名称。实现前须给出真实版本化协议、可运行示例和能力发现响应，经复核后才可替换本段“待冻结”。

## 首片支持与明确拒绝

首片拟只读受保护、完整且无删除的固定输入，使用 CF1-A 已冻结的标量 `int8/text/bool/NULL`、稳定逻辑 ID 和记录版本。SQL 复用唯一 parser/AST 白名单与 Compiler，拟消费 P05 的局部表 `records`，不是新增全局表名。过滤、投影、按列排序及常量 LIMIT 只在 P05 已验收的范围内开放；新准备模块的测试不能证明实际读取已实现。

参数绑定只用于值。完整 int8 保持规范十进制字符串，typed NULL 与缺参数分开；不能把 JSON 安全整数转换当完整 int8 支持。沿用 P05 当前设计的 SQL 16KiB、64 参数、单 text 至多4096个 Unicode 字符及总 raw/canonical 输入64KiB限制，并取部署及原 binding 更小上限。这些是输入边界，不是本页已实测的服务性能。登记的三个独立 CF1-A 值各受其1MiB合同限制；HTTP 组合封包和其它端点上限须另冻结，不能照搬查询64KiB后静默截断描述符。

首片拒绝业务 DML/DDL、CTE、JOIN、聚合、函数/外部文件、事务、COPY、多语句、任意 PG18 兼容、任意格式/codec、未认证模型/索引、缺分片或删除覆盖不完整、任意 URL 读取与媒体代理。ANN/融合、Graph、接入刷新、训练、续租和 GC 按后续子片开放，不由本页授权。没有读取能力或保护证明时失败，不切换 latest、不漏读、不把候选窗口或 SQL LIMIT 当作跳过源完整性检查的许可。

## 权限、固定绑定与重试

客户端令牌只交给认证入口，不进入 CF1-A、句柄、游标、日志或 trace。目录重新检查当前 grant、policy epoch、授权到期、目标保留和 pin。读、登记、发布、对账分别授权；登记还受当前 owner 限制。pin 保护保留而不授予读权，缓存命中也不能跳过撤权检查。失效授权不能借查询状态、错误消息或旧页泄露跨租户资源是否存在。

published 只在目录的授权/签发 pin 事务里解析一次，后续固定 dataset/schema/revision/view/source/artifact IDs 和完整 binding。并发发布不改变在途查询；explicit view 不可用时拒绝。一次查询、所有页、候选与回表共享原身份和预算，稳定逻辑 ID/记录版本不能换成物理 rowid 或批内行号。

外部查询请求、目录 BindRequest 和修改 intent 的指纹各有边界：完整查询须绑定 SQL、typed 参数、数据集/视图选择、协议及行为预算；目录 BindRequest 的持久摘要不包含 SQL，不能代替查询指纹。相同请求身份换 SQL、参数、主体或预算必须冲突；重放只恢复同一 binding/状态，不能重新 follow published 或重启总期限。网关的请求账本、重启后恢复/拒绝和指纹封包仍待冻结，未具备时不开放自动查询重试。

修改操作使用独立 operation ID、完整目标指纹与当前授权。`applied`、`rejected`、`outcome_unknown` 明确区分；网络错误或取消不证明没发生。未知时先对账同一 intent，不创建新 ID 盲重写，也不自动调整 CAS。当前授权可以更新，immutable intent 和目标不能随之变化。对账查询不到回执也不等于可重新应用，须由目录在相同 dataset 串行锁下作终态决定。

## 期限、取消与费用

服务在准入前建立一个父 query scope，等待、目录调用、准备、源/索引读取、回表、Arrow/DataFusion、编码和输出共享原绝对 deadline、只缩短的 monotonic 剩余时间和累计预算。各层取请求、宿主与合同更小上限；CF1-A TTL 最多30秒，P05 当前准入最多10秒，不能每批、每次重授权或每页重新起算。可信回调返回后重新读取时钟和取消状态；大副本及编码先完成再做最终授权和新鲜时钟检查。

所有成功、失败、超时和重试 attempt 的实际请求/字节均记账；输出、解码、保留内存、进程 RSS、IPC 与目录费用分域记录。失败费用未知应明确 unknown，不以0补齐；内存记录联合活跃量和峰值，不把单批峰值当整查询上界。结果不完整或输出超限失败，不标完整成功。

取消收到只表示已提出请求。必须核实真实 socket/子进程/任务停止、后续没有输出与后台请求，才可确认该 attempt 清理完成；丢弃 Future 或同步回调返回后的超时检查不能证明阻塞 I/O 已停止。真实 PG 重授权不能直接塞进 P03/P05 当前“有界内存、无阻塞 I/O”回调并沿用其认证。此边界由 P10/P13 bridge 的实际故障测试补齐。

成功、失败和取消后均清理原 `pin_id+lease_id`。读权过期/撤销不阻止可信清理者释放该精确 lease；旧 lease 不能释放新的 lease。清理响应未知只记录待对账，可重放同 lease 或等待目录到期；清理的独立有界等待不延长查询，也不允许继续输出。首片不承诺 pin 续租、训练交接或 GC。

## HTTP、PG 与兼容恢复

正式 HTTP 与 PG 应消费同一查询和绑定语义，逐值、NULL、完整 int8、排序、参数/权限错误和取消结论一致。HTTP 结果须能取得绑定身份、字段与行血缘、完整性/截断状态及费用；PG 普通行协议不天然携带这些证据，如何从授权的 query 身份取得对应证据仍待协议冻结，不能假称已在 PG 行中返回。

PG 保留受限 loopback、autocommit、simple/extended、参数类型与 SQLSTATE 合同；固定 Describe/Parse 的 schema 获取、statement 与 Execute 绑定时点及 portal 复用由 P05/P08 接口设计补齐。暂停 portal 继续读取须保持原 view/期限并重新授权，不能重新执行得到最新结果。发送中断若已写出部分 PG frame，应关闭连接，不追加损坏帧；HTTP 发送部分 body 后失败也不能再补一个成功完整响应。具体映射和畸形协议须用真实 `psql`/Psycopg/HTTP 验收。

旧 alpha 入口需显式保留和回归，不静默切换目录或身份模型；正式入口未启用/能力不足时明确拒绝，不回落旧 alpha 绕过权限。迁移历史数据须显式登记保留原 ID、验证新旧 reader 差异并保持单一发布权威。停用新入口不会撤销已提交目录操作、已发 pin 或外部副作用；未知结果继续对账，格式不能被旧二进制读取时不得盲降级。

## 验证与部署边界

全部新用户场景当前均为 `missing`，见[场景表](../design/fixed-entry-scenarios.md)和[变更计划](../design/fixed-entry-change-plan.md)。本轮仅先行文档；没有新服务、生产接线、PG/HTTP差异、覆盖率、性能或取消验证。模块证据不等于 I1，I1 也不等于 I2/I3 或 G1。
