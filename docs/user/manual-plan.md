# 产品手册建设合同与完成标准

日期：2026-10-19。状态：手册主干重建；完整可发布手册未完成。此页是透明的缺口清单，不能以目录存在判定完成。

## 原先缺在哪里

本轮起点的手册是 9 个 Markdown、342 行、236 非空行、17,154 个非空白字符（含命令/表格/链接）。它准确解释了有界实现，却把 SQL、检索、Graph 和训练压在一个 42 行页面，把自有数据接入交给内部设计文档。

问题不是必须写到某个页数，而是缺少对象概念、完整用户旅程、系统参考和数据库运维深度。竞品的规模与代表页分析见[产品与手册调研](../research/2026-10-19-database-products.md)；不能按文件数量给产品成熟度打分。

## 单篇任务文档的深度

每篇至少说明：适用版本/部署和权限；输入及准备；完整操作；结果/计数/版本/状态；常见失败与不支持输入；预算与质量取舍；取消/重试/清理；兼容/恢复。不是每篇都塞一份模板，信息可链接权威参考，但不能把关键步骤留给猜测。

例如接入页不能停在“配置并启动 connector”；需要说明源快照如何固定、schema/身份怎么映射、提交与索引就绪如何区分、源变化如何刷新、失败/未知提交怎样对账，以及何时对用户可查。备份页需说明恢复前提、对象闭包、冲突、授权恢复和恢复后的验证。

## 文档的验收方法

先检查相对链接与语法，再在受支持的干净部署用指定版本/样本实际执行教程，并用独立真值检查行、版本、原始证据和负例。SQL/HTTP/SDK 差异要暴露，不能各自展示不同数据然后声称统一。

未实现章节明确状态，不提供看似可执行的假命令；已实现步骤绑定实际契约与报告。文档贡献和运行时功能采用共同用户旅程验收；测试覆盖率、链接存在或生成几十个空页均不构成产品手册完成。
