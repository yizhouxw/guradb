# 部署选择与生产准备

状态：当前仅源码构建、本机受控 alpha；本页列出产品部署合同和缺口，不是已验证的生产部署教程。不得以此启动生产 HA 或升级操作。

## 选择部署方式

| 方式 | 使用目的 | 当前状态 |
| --- | --- | --- |
| 本地评估 | 合成数据、验证接口和支持边界 | 有[安装步骤](installation.md)，仍是两个服务路径 |
| 单机产品预览 | 稳定安装产物、一个数据库入口、自有数据完整旅程 | 待交付；源码脚本不等于正式安装产品 |
| 分布式部署 | 独立主机/磁盘和远程对象存储、分片/扩缩容 | 目标；本机三个 worker 不等于多机 |
| 高可用生产 | 故障域、备份、恢复目标、升级/审计/告警 | 未完成 release 验收 |

逻辑角色是入口/协调、目录/作业、查询 worker 和后台 worker，可按规模合并进程。控制 PG 与对象存储是依赖；给 PG 配 HA 不自动使整个数据库具备 HA。云托管、Kubernetes Operator 或 serverless 也没有已交付承诺。

## 容量规划应提供哪些输入

- 数据：资产/片段/边/向量数量、维度、文件/对象分布、文本/媒体大小和增长。
- 工作：查询并发、过滤选择性、候选/扇出、导出/批次读取、刷新频率。
- 布局：事实、特征、索引和历史版本放大、临时构建与备份空间。
- 资源：协调器/worker/native 总内存、SSD 缓存、远端请求/字节、网络与队列。
- 质量：精确真值/recall、相关性、冷热延迟、新鲜度和恢复目标。

当前没有按这些输入验证的产品容量模型。先在硬上限内测量，不把 synthetic 小数据或暖缓存结果换算为 PB/QPS 承诺。

## 监控与告警合同

目标应可观察服务可用性/错误、队列/取消、实际视图与索引滞后、构建/发布失败、pin/GC 阻塞、对象 I/O、缓存、磁盘/内存和操作对账。每个告警应关联用户影响、诊断步骤和恢复动作。

当前状态快照工具与日志见[运维](operations.md)，不等于生产指标/审计/告警系统。超出 128 run 等边界需要停写和生命周期方案，不能等待磁盘满才清理。

## 备份与恢复

备份需要覆盖目录、源 catalog/表版本、事实/媒体/必要特征、索引或可接受重建成本、视图和 pin，并在一致恢复点对账权限。只有 PG dump 或 Git checkpoint 均不足。

当前有冻结后的本地联合恢复，步骤见[运维](operations.md)。PITR、跨机/异地灾备、RPO/RTO 和不停机恢复未通过；索引可重建也需计算恢复/预热时间。恢复必须在新目录/独立环境演练，再验证数据、权限、训练引用和后续提交。

## 升级、降级和发布

正式版本须有 API/持久格式兼容矩阵、旧 reader/writer 窗口、进行中任务和 pin 处理、迁移前备份、失败向前修复/降级条件。不能以旧二进制能启动推定旧格式可读或数据已回滚。

生产准入还缺稳定发行产物、配置/安全指南、依赖许可/SBOM、远端 CI、完整功能/性能/故障/长稳、运维演练和逐部署模式的证据。仅本轮文档门禁通过不改变这些状态。
