# 产品、场景与基本概念

状态：产品目标指南；当前差距见[支持范围](features.md)。本文不表示完整产品已经发布。

## 适合哪些工作

GuraDB 面向已有或持续增长的 AI 数据资产：保存数据及其来源，维护可检索视图，提供 SQL 数据准备、混合检索和可复现训练读取。典型输入是文档和图片、业务元数据、外部标签/向量和实体关系；音频/视频进一步包含时间片段和对齐信息。

| 场景 | 希望得到的结果 | 先确认的条件 |
| --- | --- | --- |
| 企业知识库 / RAG | 文本和图片检索，定位原文页或区域 | 分词器、模型空间、证据位置和权限 |
| Agent 上下文查询 | 有预算、可追溯的检索与关系证据 | 工具/算子、取消与错误语义 |
| 训练数据准备 | 选样、固定版本、保持模态对齐 | split、防泄漏、来源保留期限 |
| 湖数据服务化 | 上游结果成为可查询和检索的数据集 | 格式/版本、刷新与变更白名单 |
| 推理周边数据访问 | 查找特征、相似样本和媒体片段 | 新鲜度、对象读取和预算 |

不承担高并发业务 OLTP、模型推理托管或训练调度。关系分析方向也不等于完整 PostgreSQL 事务、扩展或工具兼容；当前限制见[参考](reference.md)。

## 用一个例子理解数据

假设管理设备检修资料：PDF 的稳定资产 ID 是 `manual-42`，版本是 `v1`。第 12 页文字和示意图分别成为片段，设备型号是结构化字段；文字与图像 embedding 记录各自模型版本。关系连接资料、设备型号和故障案例。

检索应返回片段、所属 `manual-42@v1`、页/区域、命中原因与可访问原文。资料升级到 `v2` 后，旧训练集仍引用 `v1` 字节和特征。旧向量候选不能自动回到新 PDF，URI 相同也不表示字节相同。

这是目标模型示例；当前尚无完整资产/片段 API，已有实现主要管理行、外部特征与受控媒体引用。

## 数据提交与读取视图

**Dataset** 是可分析、检索或导出的逻辑数据集合。**Data revision** 固定数据、schema 和对象版本。**Read view** 再绑定用于检索的索引，使一次查询各部分读到同一组版本。

```text
接入或提交 → 固定 data revision → 构建必需索引 → 发布 read view
                                                  ↓
                                  SQL / 检索 / 训练共同读取
```

数据提交成功与搜索就绪是两个时刻。新索引失败时旧完整视图应继续使用；系统报告滞后，不能假装搜索覆盖新数据。默认读取已发布视图；显式读取最新已提交数据的补偿/等待仍是目标。

多个外部源版本可组成一个视图，但不保证同一全局事务时间。查询与训练须返回或记录实际版本集合。

## 固定视图与保留

固定 ID 或 SHA-256 不能防止上游删除对象。复现要求原始媒体、数据、必要特征和元数据都可取。托管副本和上游保护是不同责任；best-effort 来源不能保证长期重现。

**Pin** 表示查询、训练或人工消费者仍需某版本；**GC** 在保留与 pin 等条件允许时回收。数据库本地 pin 无权阻止外部湖 vacuum。释放训练结果前确认所有消费者已结束。

## 开始评估

1. 核对[当前能力](features.md)的类型、维度、规模与部署白名单。
2. 用[安装示例](installation.md)执行查询，确认错误身份与未支持语法拒绝。
3. 根据[建模](data-model.md)、[接入](ingestion.md)、[检索](retrieval.md)、[训练](training.md)核对旅程缺口。
4. 业务超出白名单时登记待交付要求，不删除预算、忽略源删除或靠跨服务拼接假定兼容。
