# ADR 0003：存储与执行技术基线

- 状态：推荐基线（本轮研究选择，实施前须通过 POC）
- 日期：2026-10-17
- 约束：[ADR 0002](0002-object-store-lake-boundary.md)
- 证据：[调研总览](../research/README.md)

## 决定

| 部分 | 首选验证路线 | 替代路线及重评条件 |
| --- | --- | --- |
| 业务存储 | S3 API 对象存储、Parquet 与外置媒体；Iceberg v2 为开放表及托管表候选 | M0 固定 manifest；M1 受限 Iceberg Snapshot reader；M2 单表 append writer 独立验收，不依赖外部多表事务 |
| AI 访问布局 | Lance 作为可重建的向量/部分列物化层 | M2 ANN 独立验证，M1 先有精确向量基线；外部 Lance reader 属于另一项兼容认证；不改变事实层为双主 |
| 执行基础 | Rust + Arrow + DataFusion，自定义检索与图计划节点 | M0 单进程查询后逐算子接入；Trino 完整服务作对照；若定制运行时成本过高则重评产品形态 |
| 全文 | Tantivy，分片不可变索引 + SSD 缓存 | Lucene 有可复用能力，但 JVM/FFI 边界另计成本；不先引入完整搜索服务双写 |
| Graph | 关系边表 + 邻接物化 + 有界遍历 | 通用图数据库、Cypher/GQL 兼容和全图计算不纳入首版 |
| 向量算法 | 精确 Flat 作基线，优先验证 Lance IVF/PQ + 重排 | HNSW 热分片对照，DiskANN/更多量化后续按 I/O 与质量评测 |
| 分布式 | 明确任务/分片/交换契约，优先评估 Ballista 构件 | 不能满足扩展算子/恢复时再决定受限运行时，避免长期两套语义 |
| 控制面 | PostgreSQL 保存小型目录/权限/作业/发布状态，REST Catalog 适配 | M0 固定清单无需可变 catalog；持久发布、提交与 HA 随切片验证，不自研共识 |
| 对外兼容 | HTTP 优先，PostgreSQL 18 SQL/类型子集基线 | wire 后续独立验收；不加载 PG 二进制扩展，不承诺完整事务与目录 |

## 选择理由

开放事实层服务湖互操作与训练扫描；派生访问布局服务全文/向量/图检索。共同逻辑 ID、版本和发布协议负责连接两者，而不是让多个数据库成为独立主表。

DataFusion 的库形态便于把检索候选和关系算子纳入共同计划，但不自动提供服务器、分布式、PG 语义或索引管理。控制面复用成熟事务数据库以缩小早期实现面；它不能承担业务数据量级。

Lance 物化接受向量/必要列重复存储。该代价需与 Parquet 随机回表、索引构建和训练访问收益同时测量，不能先假定收益大于成本。

## 未选择的路线

首版不自建完整表格式，不同步双写 Iceberg/Lance 两套主表，不围绕 DuckDB 从零实现完整 MPP，不从零补齐 Velox 上层体系，不把完整 OLAP 数据库改造当作无成本复用。它们各自有适用场景，取舍依据见[执行调研](../research/execution-and-ecosystem.md)。

## 验证门槛

按[路线图](../roadmap.md)把门槛放到引入相应能力的切片：M0 验证单进程扫描和只读 HTTP；M1 验证受限 Iceberg 固定快照、BM25/精确向量及训练 manifest；M2 分别验证 ANN、Graph、受限增量和单表 append；M3 验证真实多 worker；M4 验收发布质量。所有组件同时联编、writer 与分布式不是 M0 的前置要求，POC 代码应成为可运行内核的增量。

每个接入组件必须补齐其依赖组合、固定快照与所承诺删除、稳定 ID、PG 子集差异、冷热成本和失败恢复证据；writer 再证明互操作和未知提交对账。性能/成本阈值在测试前冻结。具体版本可按阶段固定，但生产路径中不得长期保留两套查询语义。

未通过时缩小特性、隔离成熟 writer 或重评组件；不能忽略格式删除、把 parser 当 PG 兼容或将物化层变成未声明事实源。具体版本/许可证/传递依赖在 POC 固定，本 ADR 不授权未经核查的兼容或性能声明。
