# ADR0026：目标驱动协作与PM治理责任

- 日期：2026-10-28。
- 状态：依据用户明确要求整改。规范落地与未来交付效率的实证分开；本次不恢复暂停的产品开发。
- 入口：[团队协作](../../harness/team-collaboration.md)、[五成员记忆](../../harness/members/README.md)、[领域知识](../../harness/domains/README.md)。

## 问题与决定依据

2026-10-26的组织调整保留了13个成员记忆入口，虽然称模块知识责任，仍用member_id/会话/写者恢复它们。部分长期profile还记录旧“当前任务”；本地工程索引把已停止任务保留为active。PM职责只写“不做技术”，遗漏协作制度设计/维护的正向责任，实际又代转包内技术细节。2026-10-27有并行和局部测试进展却无新增主线产品交付；停止后没有及时接下一产品目标。依据为共享根原F任务、周期review、PM复盘及成员旧记录；原失败和未知保留。

用户明确要求目标驱动、减少成员沟通、会话上下文友好，并纠正：PM就是协同负责人，应基于代码库和历史任务亲自分析优化，不需要让架构/开发讨论协作制度。本次最初错误委派已停止，治理工作由PM接回。

## 决定

1. 活跃团队只含pm/product/architecture/development/system-test五角色；PM唯一会话，其余成员身份绑定记忆、可有多个执行实例。七模块是领域知识/代码owner，integration/engineering是开发内部职能，退出活跃成员名册。旧贡献身份与原证据保留，不能洗掉作者历史。
2. PM对目标/优先级/预算/跨包资源、组织与沟通规则、记忆结构、复盘和用户承诺负责，亲自维护协作harness。产品技术交付归开发，不把技术细节收回PM微操；PM也不能把自己职责委派技术角色。
3. 一目标一张TASK，一次给目标、边界、验收和预算。开发在包内自主拆解、委派、修复、直接独验和串行集成；只在真实需求歧义/技术边界变化时用P/A，不建立五级审批链。PM只收到结果、阻塞和越界事项。
4. 开发subagent默认最小上下文，输入来自当前TASK及必要角色/领域/合同；短执行实例不扩长期成员名册。角色profile只保存稳定知识与入口，当前任务状态只存TASK，PM索引只管项目现状，历史另存。
5. 以产品增量、验收周期、等待/阻塞、返工检验效果。工具前置须对应具体验收阻断；停止后PM必须明确重排或实际待决，不能用周期review维持无限空闲。
6. 纯协作制度/记忆治理由PM完成文档验证和单独自审，不必启动技术负责人独审；明确这是自审，不能伪称独立审查。机器门禁/脚本/产品代码/安全或数据权限的改变继续走技术独审，不能混入治理来绕过。

原#19协调模式及其动态评论、长期约束索引全部撤销为历史；其旧提示不得影响仓库harness。缺本地当前状态时不回退到Issue恢复写权。

## 定向替代与保留

替代ADR0025的13责任位名册、固定模块成员及PM预定逐项接链前置；修正并行流程ROOT=PM/集成者与历史direct-main例外的活跃措辞。ADR0019/0023/0025历史事实保留，以新规范导航说明现行范围，不修改原失败。

不改变源码module owner/DAG、测试输入/超时/原21排除、正常hook/PR/精确main证据、CI暂停、真实拒绝或产品范围。50–100GB真实三模态等用户目标仍保留。此为文档/记忆组织修订，无数据库用户行为或执行器变化。用户后续明确调整前期测试策略，覆盖与全面验收的适用阶段由[ADR0027](0027-core-flow-first-validation.md)规定，机器适配仍待落实。

用户此前要求六小时架构review仍保留，暂停期间停止；自动schedule保持暂停，本次治理不授产品复工。调度prompt只管入口，规则落仓库；人工记录不声称实现跨机原子锁、身份认证或精确一次执行。

## 验收与后续验证

本次检查名册/知识/历史迁移、各活跃入口和模板的一致性，并做文档适用门禁及单独自审。完整覆盖与发现处置见[治理审查记录](../../harness/tasks/20261028-collaboration-redesign/AUDIT.md)。没有恢复产品试点，不能宣称研发效率已被证明提高；下一个由用户恢复的产品目标用真实交付数据检验。
