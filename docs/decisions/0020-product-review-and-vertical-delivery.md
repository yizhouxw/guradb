# ADR 0020：图文到训练样板与提前纵向验收

- 日期：2026-10-20
- 状态：接受产品设计与实施组织原则；新增对象、公开schema、功能、规模与生产能力均待验证
- 依据：用户要求落实本轮数据库/AI训练评审；[产品合同](../product/product-contract.md)、[训练合同](../product/training-contract.md)、[实施计划](../plans/2026-10-20-parallel-delivery.md)
- 延续：ADR0002/0003/0004的负载/技术/发布边界、0017共同数据库语义及0018模块合同、0019 PR流程

## 问题与取舍

现有alpha仍有全量MemTable、协调器全量rows及记录级split。v0.5已识别这些限制，但一次冻结全部合同、到P13才正式集成会延迟用户反馈；训练“不丢不重”也需区分导出集合与有意重复/丢尾的采样。继续扩大功能清单不能证明共同语义或训练价值。

保留模块DAG和P00–P20责任/最终门槛，采用分批合同与提前纵向验收。相比整体重写或先完成所有模块后联测，该方案更早暴露版本/授权/选择差异；代价是组合根有多次集成窗口和合同兼容管理，必须由同一owner排窗，不能各包复制语义。

## 决定

1. 首个样板为企业图文知识库→带版本证据检索→同语料embedding/reranker训练与评估数据。语言/模型、数据许可、业务真值和现有组合对照先冻结；没有客户样本时明确使用设计fixture。长期音视频、开放湖、真实分布式目标不缩小。
2. 共同目录/授权/view/查询语义优先；按需provider、批回表、流式背压及完整性验证是规模晋级门槛。保留Rust/Python合理分工，不以全库改写或增加worker代替消除全量业务记录依赖。
3. 独立定义sample身份/成员版本、分组与处理血缘；区分样本字节、顺序批次与模型结果复现。导出唯一性与消费采样分别验收，至少一种真实框架消费进入单机产品闭环。
4. 检索分算法/业务/系统三层质量；工作集按事实/向量/索引/媒体分别测缓存与成本。范围读取不能把整对象摘要误作局部校验；保留/新鲜度/替换下架作为产品合同。
5. CF1改为A共同读、B接入生命周期、C训练消费三个兼容批次；每个生产切片先冻结所需的正常/错误/故障合同。I1共同查询、I2图文接入/证据/更新、I3训练消费是既有G1内的早期真实集成点，G1–G5及M0–M4最终义务不变。
6. 公开DDL/API、采样/恢复格式、块校验协议及具体阈值仍需详细设计。不得从本文设计名推定可调用接口或允许删除源数据；不降低当前上限、覆盖率、质量门禁或历史证据标准。

## 兼容、影响与验证

本轮只修文档，没有运行时/API/持久格式迁移，不新增已支持项。后续迁移保留legacy ID/reader窗口、在途job/pin和未知结果对账；普通删除、撤权及强制擦除分别实施，完整源snapshot重建也不能忽略未支持delete语义。

本ADR细化0018的合同冻结/集成顺序，不替代模块归属；路线图仍是阶段范围权威。验证是文档一致性、可执行依赖、评审映射及适用harness门禁；源码事实和未来验收分别记录于[落实复核](../reviews/2026-10-20-product-review-followup.md)。没有新增数据库运行时测试通过或生产承诺。
