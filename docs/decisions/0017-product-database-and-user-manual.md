# ADR 0017：产品级数据库交付与用户手册纠偏

- 状态：接受产品/工程组织原则；新增功能、接口和部署均待实现验收
- 日期：2026-10-19
- 依据：用户明确要求重新审视产品级、多模态、AI 场景数据库目标；[官方产品调研](../research/2026-10-19-database-products.md)、[现状复审](../reviews/2026-10-19-product-direction.md)
- 延续：ADR 0001/0002 的目标与非 OLTP 湖边界、ADR 0004 的事实/视图不变量、ADR 0016 的文档先行

## 问题

愿景和功能架构已描述数据库目标，但工程切片逐渐替代用户成果。九页手册主要讲 M0/M1/M2、脚本、限制和证据。SQL 与检索有两套目录/授权/版本入口，资产/片段/特征仍停留在目标表格；继续只补单项模块会固化偏移。

## 决定

1. [产品交付合同](../product/product-contract.md)作为完整用户旅程与对象要求；[路线图](../roadmap.md)继续是 M0–M4 范围唯一来源，按产品成果重排执行。旧阶段通过不追溯扩大，组件证据仍保留。
2. 用户对象、稳定管理入口和端到端流程是产品交付单位。外部湖与托管数据集并重；数据库承担接入/版本/索引/查询/治理责任，不长期让用户手工拼脚本和产物。
3. 收敛为一个逻辑目录、授权与读取上下文及共同查询语义。PG 控制面与 Rust 查询基础仍沿 ADR 0003；Python 可以保留后台编排/生态适配，不保留独立产品真值。具体迁移按兼容切片，不要求整体重写。
4. 多模态需有资产、片段、坐标、处理/模型版本、特征与关系的可操作合同；媒体引用、解码和模型处理分别验收。首条垂直闭环选择文本+图像，音频/视频逐模态推进。
5. SQL 数据准备、混合检索证据、训练选择/读取及可安装管理是共同产品主线。关系关联/聚合不再无限后置；每个算子/格式/API 先设计和验证再标支持。
6. 手册按概念、教程、任务、系统参考和管理员职责组织。内部里程碑/commit/harness 是工程证据，不是入门概念；保留版本白名单与限制，目标章节明确待实现。
7. 不机械匹配竞品页数，不预建空页面，不用目标伪造命令。完整发布需要干净环境按手册完成任务、独立真值/负例与实际恢复演练。

## 取舍与未决项

这会增加统一目录/执行和产品管理入口的优先级，推迟缺乏用户闭环的新算法/连接器扩张。A1 选样、A2 按需读取、A3 生命周期保留为必要工程工作，但不能单独代表产品完成。M2 目标补入单机产品闭环；M3/M4 的多机/生产门槛不降低。

项目/namespace 命名、资源 API/DDL、坐标 schema、跨表关联、统一错误与配置、迁移格式、发行策略和工作负载预算仍需详细设计。本文接受方向与约束，不接受未经 POC 的性能或组件实现承诺。

## 验证和影响

本轮仅修研究、方案与文档，无数据/API/运行时变更；文档门禁和独立复核不能证明数据库功能增长。最终证据由 `product-direction-correction` task receipt 绑定。后续实现按用户文档先行、版本化契约、功能/质量/故障门禁验收。
