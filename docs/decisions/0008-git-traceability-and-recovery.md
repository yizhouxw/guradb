# ADR 0008：Git 追溯与安全恢复

- 状态：已采用的工程约定；本地工具与私有远端已接入；2026-10-20用户授权后续开发提交经验证后直接推送现有origin
- 日期：2026-10-17
- 依据：用户要求版本管理接入 agent harness，使开发可追溯、阻断错误可回滚
- 规范：[Git 工作流](../../harness/version-control.md)

> 2026-10-20后续决定：[ADR 0019](0019-pr-parallel-development.md)将直接main与本地合并推送改为独立分支/worktree、GitHub PR审查与串行合入。下文单人主线与推送段落保留历史依据；当前操作以0019和Git工作流为准，恢复/证据不变量继续有效。

## 决定与取舍

使用已有 Git 仓库，建立首个项目基线与不可覆盖的 checkpoint tag。开发按有限切片提交，记录起始/最终 commit、质量报告与 checkout digest；当前单人开发默认直接在 `main` 完成，已有工作分支完成后合入 `main`；只有并行开发同一大需求时引入多分支，每个分支使用独立 worktree。已有用户改动保持原样，失败现场按恢复流程在新目录验证。提交前 hook 运行同一 change 门禁，并拒绝未暂存/未跟踪的工作区，避免验证与提交内容不同。

`checkpoint` 只标记干净的已提交状态，证据匹配时在 annotated tag 中保存实际验证 scope 和摘要；不以恢复点名字代表产品质量。`recover` 在新目录建立 detached worktree，保留当前失败现场。当前分支撤销采用经复核的 revert 新提交，不重写历史。默认不执行破坏性 reset/clean；推送授权按下方2026-10-20补充执行。

本地 hook 可被绕过，tag/对象也可人为删除，不能冒充不可篡改审计或异地备份。远端保护与数据备份另行配置。代码回滚不撤销持久数据和外部副作用，恢复前必须对账并采用对应迁移/数据恢复方案。

## 验证

真实临时 Git 仓库测试覆盖 unborn/dirty 检查点拒绝、报告与 commit/指纹不匹配拒绝、恢复旧文件且保留当前 dirty/untracked 文件、拒绝覆盖目录、staged 快照检查和既有 hook 配置保护。实际本仓库安装 hook 并执行提交前门禁；上述为最初 bootstrap 阶段的验证，当前运行时能力与质量范围见 README 及对应 commit 报告。

## 2026-10-18：单人主线工作流

依据用户明确要求，完成后的代码以 `main` 为交付位置。普通任务直接在主线提交；大需求并行期间才使用独立分支/worktree，完成后经门禁和复核合回主线。优先快进，历史分叉时保留历史正常合并；主线验证覆盖合并前基点到最终 commit 的完整范围。恢复点、用户改动保护及推送另行授权保持不变。

## 2026-10-20：提交后直接推送现有远端

依据用户明确要求，本仓库后续开发在门禁、复核及提交后验证完成后，直接将开发提交推送到已配置的 `origin`；普通任务在 `main` 完成并推送，不再逐次请求确认。该授权替代本ADR此前及旧任务材料中的“推送另行授权/不自动推送”限制；历史记录仍保留其当时边界。

推送前fetch核对远端，禁止强推、覆盖远端新提交或绕过hook。checkpoint tag不默认批量推送；更换远端、权限/保护设置、发布和部署不包含在普通开发推送授权中。推送后核对GitHub Actions的实际状态，本地通过或推送成功均不等于远端CI通过。

本次只更新协作约定，无数据库用户行为、持久数据或API变化；适用文档门禁、提交后报告与checkpoint照常保留。
