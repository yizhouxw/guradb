# ADR 0022：按模块交付、真实配对与四层验证

历史注：文中的Issue19协调及ROOT人员安排已被[ADR0026](0026-goal-driven-collaboration.md)撤销；验证的阶段优先级以[ADR0027](0027-core-flow-first-validation.md)为准。历史技术结果保留。

日期：2026-10-21。状态：接受用户要求的实施原则；机器接线和当前能力分别以 task/报告验收。

## 背景

CF1-A、独立真值与多个模块已有实现或组件证据，正式用户链仍未接通。单个模块反复执行整库 Rust/Python/功能/成本/故障，叠加环境恢复和原件整理，延迟了生产者与消费者配对。以大工作包、角色数量或最终绿灯数量报告进度不能说明用户交付速度。

## 决定

1. [细粒度需求矩阵](../product/requirements-v2.md)是分配单位；每行有唯一验收 owner、支持/拒绝、依赖、正负真值与预算。PG 物理页导入独立研究/原型，不降为 wire 或逻辑导入。
2. [模块合同](../design/module-delivery-contracts.md)先明确输入/输出、错误/DAG、预算、真实依赖和唯一写权；必要复核后即实现，以真实配对持续校正，避免等所有合同/整个包完成。
3. 模块、配对、系统、发布分别验收。模块保持完整 owner 生产源严格覆盖、自身真实依赖和功能/性能/恢复；跨包可固定 fixture。系统/发布放到对应集成与发布窗口，missing 不变绿。
4. ROOT 承担 PM；产品、架构、开发、测试、文档按实际四槽分时兼任，作者与独审分开。同一文件/组合根/迁移单 owner，普通无污染模块验证允许并行，性能只独占其受控资源。
5. SQL/Arrow/DF 由 Rust 唯一解释执行。已实现 Python 后端保持各自过渡权威；迁移需真实消费者差异、失败/预算/恢复与切换回滚证明，默认只启一个 adapter，不长期双语义演进。
6. 正常 pre-commit/PR 按机器 registry 选范围，报告/receipt 绑定层级、源闭包与选择器版本；过窄显式要求拒绝。未知影响扩大检查，完整发布依然要求实际完整门禁。

## 结果与约束

完整产品义务、稳定 ID/版本、双 fencing、unknown 对账、pin/撤权、原性能负载及恢复纪律保持。模块 100% 不证明系统正确，计划/registry 不证明模块能力。本机模拟仍不等于真实云或独立物理三机。

该决定允许以经验证模块小片合成连续集成批次；不允许绕过 hook、改原始 task base、伪造 fresh 报告或复制不匹配的性能计数。现有 dirty/失败现场保留，已有有效证据沿用原绑定。远端 PR/CI 与精确 main 候选仍实际核验。

落实与首批任务见[策略 v2](../plans/2026-10-21-modular-delivery-v2.md)；门禁代码由 `gates-v2` 独立任务实施并由非作者复核，不能仅改文档宣布已完成。

2026-10-24角色更新：上述ROOT兼任PM为历史组织。当前独立PM会话经GitHub Issue19负责优先级/依赖/阻塞升级/交付跟踪，ROOT负责实施验证集成；原验收与文件唯一写权不变。
