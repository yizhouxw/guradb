# ADR 0016：用户文档先行与场景验证

- 状态：已接受工程约定；源自用户明确要求
- 日期：2026-10-19
- 前置：ADR 0007/0009；[开发流程](../../harness/development-workflow.md)

## 决定

建立 [docs/user](../user/README.md) 作为对客手册，覆盖产品功能、技术架构、安装部署、使用、运维、开发、诊断与验证状态；工程设计、研究和 ADR 保留其独立职责。

后续新增能力及可观察行为修复先更新用户合同，描述操作、结果、支持/拒绝范围、权限/预算、兼容/恢复并标记待实现，再实现并执行文档对应成功和负例。纯内部改动需记录用户行为无影响的依据；纯文字修订可轻量验证。文档可与实现同一最终提交，先后顺序由实现前 diff/任务记录或文档先行提交提供复核依据。

完成复核必须核对手册场景、版本化契约、能力清单、测试真值和实际报告；未验证不标支持。仓库检查验证必备页和相对链接，功能/性能/故障证据由相应真实 driver 提供。当前不增加自动编辑时序判定器，也不将链接存在当命令正确或产品通过。

## 理由与代价

用户合同先固定，可暴露部署前提、失败/拒绝行为和兼容缺口，避免实现完成后补写出超出证据的承诺。代价是每个用户可见变更均需维护手册及验收映射；手册以公共使用流程为主，细节链接权威运行合同，减少多份参数定义漂移。

## 验证与适用

本次页面、链接、示例和门禁结果见[手册验证](../user/validation.md)。已存在的覆盖率任务/脏工作区不覆盖、不自动提交；本次文档工作不扩展数据库能力，也不替代当前运行时缺口收口。
