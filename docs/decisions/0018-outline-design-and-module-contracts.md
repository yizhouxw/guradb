# ADR 0018：概要设计基线与合同驱动的模块并行

- 日期：2026-10-20
- 状态：接受文档组织、责任边界和并行开发原则；公开合同的具体schema、技术实现及性能/云/安全能力仍待详细设计和验证
- 依据：用户要求完整概要设计及可并行实施计划；[概要设计v0.5](../design/outline-design.md)、[官方竞品证据](../research/2026-10-20-outline-design-evidence.md)
- 延续：ADR 0002非OLTP湖边界、0003技术POC、0004版本/发布、0007里程碑与门禁、0016文档先行、0017共同对象/目录/查询

## 背景与选项

原架构已确定技术构件和共同语义方向，但业务场景到非功能目标、模块端口和并行任务之间缺少完整映射。继续按串行功能清单开发会等待上游全部完成；直接多模块并写则容易产生各自的授权、版本、错误和发布语义。

比较三条路径：整体重写/一次拆微服务扩大迁移与运维风险；仅给现有脚本加统一网关保留两套产品真值；先冻结公共合同、按模块独立实现并在有限波次真实集成可复用现有代码且暴露必要依赖。采用第三条。竞品角色划分用于理解责任，不能照搬进程数量或把Cloud能力当开源构件。

## 决定

1. 用S1接入、S2混合证据、S3训练、S4生命周期、S5治理部署关联产品J1–J6。概要设计的每类架构与质量专题均记录场景、竞品证据、目标、方案/代价和验证；技术推荐不升级为支持声明。
2. `common`只承载稳定值/低层端口；storage管对象/缓存，connectors解释格式与源提交，catalog管目录/授权/pin/发布，index管派生产物/候选，cluster管任务与配额，query管共同规划及应用编排，gateway管协议。客户端共享薄客户端合同。按现有机器DAG依赖，不引入反向模块调用或共享私有状态。
3. 事实权威、源提交权、目录发布权与任务租约分别表达；跨模块只交付版本化描述符/显式端口/Arrow批次。单目录/授权/固定view、源与目录双fencing、未知提交对账、GC/pin/撤权和端到端预算不可由各模块重新定义。
4. 并行准入物是公共合同与正常/错误/故障fixture，不是上游全部实现。fake仅供隔离开发；真实peer合同测试和逐波用户旅程集成才是完成依据。合同演进保持双版本窗口，破坏性变更集中复核，不由工作包自行修改共享类型。
5. [并行实施计划](../plans/2026-10-20-parallel-delivery.md)替代2026-10-19计划的任务顺序，吸收D1–D6/A1–A6必要义务。M0–M4范围仍只在路线图维护；不建立另一套产品阶段，不降低原质量门槛。
6. 估算是给定并发角色与资源下的人周区间；样本、性能/成本预算与依赖POC到位后重估。不得把提案档位、CloudAdapter接口或合规控制清单当作已测SLO、已认证云或合规结论。

## 影响、兼容与验证

本轮只修改文档，没有新API、schema迁移、持久格式或部署副作用；旧alpha入口与白名单保留。后续先登记现有manifest并统一解析，逐条迁移SQL/检索/训练，替代范围通过前不移除旧reader。持久升级需在途Job/pin、旧reader窗口、未知结果和向前恢复合同。

复核重点为模块DAG/调用编排一致性、没有共同数据库表后门、四槽位计划可执行、每项依赖有交付物和验收、证据/edition边界明确。文档门禁不能证明性能或数据库质量；最终证据绑定本轮task receipt，内容复审见[设计复审](../reviews/2026-10-20-outline-design.md)。
