# ADR 0023：固定模块团队、独立 Issue 与本机质量阶段

当前组织/沟通规则见[ADR0026](0026-goal-driven-collaboration.md)。本页固定模块成员/Issue前置属历史；CI暂停与质量义务保留。

> 2026-10-26 定向替代：[ADR0025](0025-local-member-memory-and-task-delegation.md)采用本地任务权威、稳定member_id/成员记忆和统一开发负责人按任务委派；旧强制Issue及固定成员会话条件不再适用。下文保留历史合同；普通分支/PR、作者独审分离、本地质量、预算与CI暂停仍保持。

- 状态：接受，2026-10-24 用户明确授权；团队席位的具体任命须在 Issue 登记
- 依据：用户要求核心模块设开发负责人，配套架构、产品、专职系统测试；每人工作独立 GitHub Issue/模块标签；暂停 GitHub Actions CI/CD 和 PR CI 卡点，当前靠本机自测；本次治理变更直接提交 main
- 规范：[团队协作](../../harness/team-collaboration.md)、[PR 集成](../../harness/parallel-development.md)、[本机质量与 CI 暂停](../../harness/ci-cd.md)

## 决定

七个核心模块各设稳定开发 DRI，产品/架构/系统测试/集成/PM 分责；逻辑 12 席按执行容量调度。common 由架构师维护。作者负责模块自测，专职系统测试独立负责真实配对和系统验收，集成者负责最终 main，PM负责排程和范围收敛。

所有后续成员任务先查重后建独立 Issue，必须有主 module 标签、role 标签、GitHub assignee、完整 DRI/session、验收、文件/资源边界、依赖/关联 PR、下一动作与检查时间。总协调 Issue 仅汇总；未验收不关闭，撤销/重复必须注明接续与保留现场。标签由PM派发前核对，不声称表单自动贴标或已启动所有成员。

当前 GitHub Actions 工作流由仓库 API 显式停用，保留配置供将来评估；取消两个 quality job success 作为 PR 合入条件。本机适用自测、独立复核、源码绑定证据、正常 hook、恢复点与精确 main 验证仍必须真实完成。CI 记录为 paused/not-run，历史失败保留，不能改称 PASS。托管 runner 容量问题不成为本机质量阶段新增 CI 工具的前置；本地测试预算和负载不改。

本决定修订 ADR0019/0009 及旧文档中的远端 CI 必需条件；其他分支隔离、PR 审查、串行合入、非破坏恢复原则保留。用户对本次治理任务明确授权直接提交 main：准备可在隔离目录完成，最终由单一集成者在最新 main 串行直接提交、正常推送并核验，不强推。普通后续任务仍默认独立分支/PR，除非用户明确另行授权。

## 影响、验证与恢复

这是协作与工程质量组织变更，无数据库接口、布局、预算、权限或数据迁移变化。完整产品/性能/故障/长稳/release 义务不因暂停远端CI被认定通过。

核对任务模板/标签清单、全部规范入口、本地合同/harness/政策/仓库检查以及远端 workflow disabled 状态；本地自测仍是合入质量依据。工作流定义保留、活动运行单独核查，暂停状态见 [ci-state.json](../../harness/ci-state.json)。

恢复CI须用户重新讨论并授权：先固定受控部署/runner、完整命令/时间容量、凭据与日志、真实候选运行，再确认 required checks 的名称和平台保护规则，明确新的ADR后才恢复。恢复workflow或修改YAML不等于真实CI通过，CD仍需发布/环境授权。代码回退不自动重启远端工作流或撤销已发生外部配置，需独立对账。
