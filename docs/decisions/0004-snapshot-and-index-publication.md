# ADR 0004：数据版本与索引发布

- 状态：推荐基线（待状态机和故障 POC 验证）
- 日期：2026-10-17
- 关联：[架构](../architecture.md)、[存储调研](../research/lake-storage.md)

## 问题

湖表提交、全文/向量/图构建和 GuraDB 目录变更不在同一跨系统事务中。若索引各自追逐最新数据，会出现旧候选配新数据、删除残留、训练样本变化或多次发布。

## 决定

1. `Data revision` 固定精确的源表/对象/schema 版本集合；`Read view` 再固定该 revision 与对应索引清单。
2. 数据提交与检索就绪是两个状态；默认查询固定已发布 read view，最新已提交数据读取显式请求。
3. 不满足完整性/新鲜度时等待、在预算内做正确补偿，或明确失败；不能静默漏候选。
4. 训练和分页 pin 读取视图；外部源不能保留所需版本时，选择托管副本或明确复现限制。
5. 物理行号不是跨格式身份。索引产物绑定稳定记录/片段 ID、记录版本、源 revision、模型/分析器/构建配置。
6. 发布为目录内的原子指针切换；任何索引构建失败都不使一个不完整索引组合替代旧视图。
7. 普通数据删除按 revision 可见；授权撤销/强制擦除单独门禁，不被旧视图或缓存绕过。
8. 默认查询只绑定已发布 read view 中的源版本，不重新解析源最新；刷新和显式 `data_committed` 单独固定目标并证明覆盖。对象失效后只能重试相同版本，不能换最新后沿用原视图身份。
9. 记录身份遵循[数据与查询契约](../product/data-contracts.md)；无可靠稳定键的源允许固定快照扫描/全量构建，不据此承诺跨版本逐行增量。

## 必须保持的不变量

- 发布任务的目标 revision、构建 generation 和来源不可在重试时被悄悄改成别的值。
- 目录 CAS 同时校验预期旧指针、当前任务/租约及目标 generation；旧任务不能重新读取新指针后把已发布视图倒退。
- 显式回滚也是一个新的发布操作/epoch，不能伪装成旧任务继续成功。
- GuraDB 发布 fencing 与源 catalog 提交 fencing 分开验证；前者不自动阻止失效 worker 在外部源生成快照。
- 托管 worker 只生成数据/索引产物，源提交经受控提交入口。后端不支持所需 fencing 时，结果未知必须对账，不宣称所有孤立源提交都已被阻止。
- 首个托管写入切片仅单表 append，同表提交串行且不接受旁路外部 writer。未知或未对账源提交阻止同表后续提交及依赖它的发布，直到按 job、父版本与精确快照确认；不能让后续 append 从未知 HEAD 继承半成品。源提交已确认而索引尚未就绪属于正常滞后，不回滚事实数据。
- GC 同时考虑源格式引用、已发布视图、活跃查询、训练 pin、保留及外部所有权。
- 内容摘要仅用于身份/完整性验证，不提供历史字节保留。数据集登记 `upstream-protected`、`managed-copy` 或 `best-effort` 等级；托管副本必须覆盖媒体、元数据/删除信息和必要特征等完整依赖闭包，否则仍依赖外部保留。本地 pin 不阻止上游 vacuum/过期；`best-effort` 不承诺长期复现。
- 托管 GC 在目录事务中先标记 `retiring` 并拒绝新 query/train/build pin，等待已有 pin、保留期与安全期后再经格式维护协议清理。不得直接删仍被源格式引用的对象；外部源只通过已认证上游保护协议协调保留，不由 GuraDB 擅自回收。

## 原子性范围

此机制为通过 GuraDB 目录访问的读者提供固定版本集合；read view CAS 不构成跨表业务写入事务。首个 writer 不接受多表原子写作业，上游多表结果由完成清单或显式版本集合绑定。多表写入若后续引入，必须独立解决中间提交隔离、恢复和后续写入基线，不能只依靠发布指针。此机制不是跨外部湖的 2PC，不保证外部直接查询底层表的读者看不到中间提交。REST Catalog 多表事务是否存在及可用需独立发现/认证。

## 验证

在上传前后、源表提交前后、data revision 发布前后、单路索引完成及 read view 发布前后注入崩溃。覆盖重复 job、过期 worker、旧构建晚完成、提交结果未知后启动下一次 append、删除与 GC/新增 pin 竞争、外部 vacuum、权限撤销和分页重试。验证 hash 一致但对象已不可取、托管表仍引用未发布文件、媒体未复制的所谓完整导入等负例。

通过条件是：已确认提交不丢；旧合法视图保持可用；未发布半成品不进入查询；同一逻辑写入不被盲目重复；不存在旧任务造成的版本倒退或无诊断的混快照结果。尚无上述测试结果。
