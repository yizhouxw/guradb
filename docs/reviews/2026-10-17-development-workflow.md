# 开发流程复审与实施计划

状态：实现与单独复核已完成，实际验证以当前 commit 的 harness 报告为准。

## 基点、范围与恢复

开始时主线干净，起始 commit 为 `d0c09722571bef155c4806fc1a12de315757f7e0`，恢复点为 `checkpoints/20261017T082320Z-before-workflow-review-306048ba`。本轮是 task receipt 工具的首次引入，按原 Git 流程以显式 base 检查/提交/建证据检查点；后续非小型任务使用新任务命令。

用户要求复审开发闭环，并确认 GitHub Actions 可作为 CI/CD 平台。范围为开发工具、门禁与协作规范；不实现数据库内核，不操作远端、发布平台或部署凭据，不改变已有性能/故障阈值和产品边界。

## 具体缺口与修正

| 缺口 | 风险 | 修正 |
| --- | --- | --- |
| 原始任务 base 仅手写 | 多次提交后空差异检查漏掉已提交功能 | task receipt + 本地 auto 沿用 base，结项强制同范围 |
| 检查中仅验证源码指纹 | HEAD 在执行期间变化，报告归属错误 | 所有 check 额外验证 HEAD 未变 |
| checkpoint 只核对报告头 | 缺 suite/空命令或篡改日志仍可能被标为通过 | 重算 policy/变更、核对全部命令/日志，负例测试 |
| artifacts 被清理后只有 tag 摘要 | 无法取回验证细节 | 成功 checkpoint 归档原始报告/日志/映射 |
| workflow_dispatch 的 auto 可能空差异 | 手动运行漏掉干净树已提交内核 | 默认全树，允许显式 base |
| CI 总时限与运行门禁预算未对应 | 长稳未完成即被 job 杀死 | 普通/完整预算分层并测试，后续按环境拆 job |
| 需求/完成/失败/迁移/交接分散 | 扩大代码规模后交付口径漂移 | 统一开发流程和计划/PR 模板，保留轻量文字修订路径 |
| CD 没有服务或目标环境 | YAML 假成功冒充部署 | 明确不可变产物、环境晋升与恢复前提，待真实服务接入 |

## 实施与验收

按 task state → check 范围/日志 → 报告校验与归档 → lifecycle CLI → Actions 配置 → 规范/导航推进；互相引用的开发工具一起验证。plan 要求 repository/policy/contracts/harness-tests，没有数据库运行路径；局部测量/数据库故障与 soak 不适用，仍保留 planned。

验收基于真实临时 Git 仓库和实际子命令：多提交范围不丢、重复任务/分支异常/dirty 结项拒绝、停止保留文件、state 按 worktree 隔离、原始 base 不符和 bootstrap 结项拒绝、缺/重复 suite、失败/空/替换命令与篡改日志拒绝，成功归档可读；CI 对照实际超时预算和权限/输入/上传约束。最终本仓库经 hook 提交，再以起始 base 重验并建证据 checkpoint。

## 复核与剩余前提

在实现后单独检查状态归属/锁、Git ref/路径处理、报告与 policy 范围、破坏性动作和 CI 事件。报告不是防伪证明，review 文本不证明独立审查，receipt/归档不随 Git bundle 备份；远端首跑、保护规则、受控性能 runner 和 CD 合同仍待配置，不以本地工具测试冒充通过。

复核另修正两处实际断点：hook 安装必须保护从全局配置继承的自定义 hooksPath，且 POSIX 下非可执行 hook 不得宣称已安装；任务历史先于当前 receipt 原子更新，减少中断后审计状态落后的窗口。相应负例纳入测试。未删除原有用例或放宽发布门禁。
