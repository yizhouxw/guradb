# 记录身份、版本与可复现读取合同

状态：实施基线；M0落实固定manifest/视图、键编码向量与受限读取；M1增加单字段稳定键全量校验、managed-copy快照/索引/训练pin与发布恢复，具体白名单见[M1合同](../design/m1-snapshot-serving.md)，覆盖见[M0验收](../design/m0-validation.md)。适用于扫描、全文、向量、图、增量同步和训练；范围依 [路线图](../roadmap.md) 逐片实现。

## 记录身份与空键、重复键

稳定身份为 `(dataset_id, entity_kind, logical_key)`。`dataset_id` 是目录分配、受租户隔离约束的不可复用 ID；`entity_kind` 区分 record、asset、segment、node、edge，避免相同业务键跨实体冲突。向量空间/模型版本是索引命名空间，不改变事实记录身份。

首个稳定键子集采用有序的 `text / int64 / uuid` 非空字段元组。注册时冻结字段顺序和类型：text 保留 UTF-8 字节且不做隐式大小写/Unicode 归一化，int64 使用有符号整数值，uuid 使用 16 字节值。编码带版本、类型标签、元组项数和各项长度，禁止简单分隔符拼接或语言默认 hash；缓存键、RRF 去重、回表和 manifest 使用同一编码。实现时将编码测试向量作为 M0 合同，未验证的键类型明确拒绝。改变键字段、类型、顺序或编码版本需要新身份命名空间或专门迁移。

| 来源/用途 | 身份规则 | 失败与限制 |
| --- | --- | --- |
| 托管导入 | 用户键先校验非空与全局唯一；未提供键则分配 ID 并将其作为事实列持久化 | 重试复用持久 operation/导入记录中的 ID 映射，不能每次重生成；ID 分配协议在托管写切片实现 |
| 有键外部源 | 显式配置键映射，首次 Snapshot 对整个结果集验证非空和唯一 | NULL/重复键使该版本构建失败，保留上一已发布视图；不能 last-write-wins 或静默去重 |
| 无可靠键外部源 | 允许固定快照扫描和全量索引构建；使用 `(revision_id, immutable_fragment_id, row_ordinal)` 的快照内唯一身份 | 它不是跨版本逻辑键，不能跨版本复用索引、做逐行增量或承诺稳定训练样本 ID；文件重写产生新 revision 与新身份 |
| 关系/片段 | 端点/父资产引用完整身份；片段和边也有自己的 ID | 悬空、跨租户、版本不匹配的引用在构建时拒绝，不能靠物理 rowid 猜测对应关系 |

验证唯一性不能只抽样；大表可分区排序/聚合校验，成本纳入构建指标。增量复用还需校验新键不与既有键冲突；缺少这一能力时只允许 Snapshot 全量构建。

## 记录版本与源版本

`record_version` 与逻辑身份分离，凡影响返回结果或特征/过滤/关系的内容变化必须产生新版本。首个 Snapshot 实现可将不可变 `data_revision_id` 作为该 revision 内全部记录的版本，整版重建索引；不要求先实现通用逐行内容 hash 或 CDC。

首条 append-only 增量持久继承父 revision 的身份/版本映射，仅为新记录分配版本；检测既有键再次出现、删除、rewrite、回滚或不支持的 schema 变化时，明确失败或按预先配置转独立 Snapshot 重建。不能把一次触发自动解释为“可安全逐行增量”。更细的源记录版本/内容 hash 方案须另冻结 canonicalization、删除和模型输入规则后才允许复用。

源快照 ID、GuraDB data revision、索引 generation 和发布 epoch 分别标识不同事实。一个索引声明覆盖哪些 revision/记录版本及特征定义；不能仅因业务键相同就把旧 embedding 或旧全文命中当作新记录结果。Embedding 由首批调用方提供，必须声明模型/空间 ID、维度、距离和预处理版本；不在首次切片内隐式下载模型或重算全部媒体。

## 查询视图和发布范围

一个 data revision 是不可变的资源版本清单；一个 read view 在此基础上固定可用的索引 generation、特征/过滤定义和发布 epoch。多数据集查询在开始时从 GuraDB 目录一次性绑定所需已发布指针，形成查询级的 opaque revision/view 上下文；响应列出所有源版本。它提供固定的版本组合，不承诺多个独立上游发生过全局同一时刻的业务事务。

服务定义明确必需的索引 bundle。仅扫描的服务不等待无关 Graph/ANN；需要全文与向量融合的服务则必须等两者覆盖同一 revision 才发布。一个服务允许多个能力视图时必须明确绑定规则，不能在单次查询中临时拼接各自最新索引。查询请求超出已发布能力时明确拒绝或执行同版可验证的精确路径，不能静默漏候选。

默认 `published` 读取只从选定 read view 取源版本。显式 `data_committed` 属后续能力，绑定目录已提交的确定版本组合，并逐项证明精确扫描/补偿或等待覆盖；它不是重解源最新或免除一致性校验的开关。分页、重试、训练 manifest 与导出沿用同一组合，旧对象缺失即报历史不可用，不切换最新继续返回。

## 对象保留与访问边界

摘要证明字节完整性，不能保证旧字节仍可读取。可复现读取要求不可变 key/对象版本及实际保留机制，且依赖闭包包括媒体、片段、特征文件和格式元数据。

| retention_mode | 保留责任 | 可承诺范围 |
| --- | --- | --- |
| `upstream-protected` | 上游明确保护所选快照和对象，期限/续租及失败行为可验证 | 在约定保留期内可复现；GuraDB 本地 pin 本身不能延长上游期限 |
| `managed-copy` | GuraDB 持有并保护完整依赖闭包的托管副本 | 在本地 pin/保留政策内可复现；只复制 Parquet 或索引不算完整复制 |
| `best-effort` | 上游无可验证保留保证 | 可用于当前检索，但历史可能失效，禁止承诺长期复现；失效时明确报错 |

托管 GC 先在目录事务中将版本标记 retiring 并拒绝新 pin，再等待已有查询/训练/构建 pin 释放及安全期，最后经格式维护协议清理。未对账的源提交不能当作垃圾。外部源 GC 不受本地目录控制，必须通过保留约定或托管副本解决。

权限在每次新请求、分页取数和任务执行点重新检查。撤权阻止后续受控访问；已经返回的字节、直连上游和仍有效的外部签名 URL 不可由本地目录追回。需要严格撤权的服务经受控读取代理返回数据；直接分发访问凭据/URL 必须采用独立的最短有效期与源权限合同。

训练sample与record身份分离，保存成员角色/完整ID/version、recipe、标签/特征、group/split映射和依赖闭包。选择集合唯一性与采样重复/补齐/丢尾分别验证；样本字节、顺序批次、模型结果复现分层，详见[训练合同](training-contract.md)，当前记录哈希split不自动具备分组防泄漏能力。

## 新鲜度与保留承诺（目标，待实现）

新鲜度绑定具体源版本及覆盖水位，observed/committed/indexed/published分别计时；最近轮询时间不能证明已覆盖该时刻的数据。显式新鲜度请求预注册计时依据、最大滞后和等待预算，无法证明满足则等待/失败，不能改为各算子重取latest。固定历史回放不默认追求新鲜数据，冲突约束须明确拒绝。

保留承诺登记责任方、全部依赖、期限、续期结果、pin/释放与字节配额。上游保护失败告警并拒绝新的不可兑现承诺，既有承诺受影响须对账披露；不能自动改为best-effort。获得授权并完成闭包复制/校验后才可切换托管保护。普通替换/下架通过新revision表达，历史保留、撤权及强制擦除是不同状态，不以删除最新索引代表全部副本清除。

## 各切片的验收义务

M0 冻结键编码、固定 manifest/对象版本、只读绑定和错误语义；M1 验证全量唯一性、同版索引回表、发布恢复和保留模式；M2 增量/托管写分别验证继承映射与幂等对账；M3 验证跨 worker 的同版去重、排序与取消。独立真值、负例与故障测试未通过前，不扩大对应能力白名单。
