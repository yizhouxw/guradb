# 下一阶段行动计划：补齐数据准备与可扩展读取基础

日期：2026-10-18。依据：[当前功能与架构复审](../reviews/2026-10-18-capability-architecture.md)。
状态：A0 有界实现及切片验收已完成，主线最终 commit/报告/checkpoint 由 `a0-main-integration` receipt 绑定，见[A0集成复核](../reviews/2026-10-18-a0-integration.md)。A1–A6 仍待实施；PG wire 首片已独立合入 main，未改变 A1–A6 的执行面缺口；不新增已接受的技术选型，不改变[路线图](../roadmap.md)的 M0–M4 退出条件。

## 1. 阶段目标与范围

首要场景沿用现有项目方向：Iceberg 固定快照/外部特征用于 RAG 检索和训练数据准备；本次没有新的业务数据集或规模要求，因此先冻结负载与预算，不承诺日期、QPS、p99 或 PB 规模。

用户可观察的阶段成果：

1. 对同一已发布 read view 筛选/投影训练样本，经 HTTP、CLI、MCP 导出一致的身份、版本、split 与 Parquet；新发布不改变已受理任务的结果。
2. 在固定输入、质量和预算下，协调器只持有视图描述符、有界候选与结果批次；worker 读取分配产物。扩大数据量前拿到真实资源证据。
3. 持续构建/发布/回收超过当前生命周期阈值仍可诊断、可对账，不丢已确认提交，不把旧 operation 当新写入。
4. 明确 M2 剩余质量项是否通过，并形成跨机只读 POC 的输入合同和 go/no-go 证据。

继续支持现有白名单及旧 bundle 兼容路径。新增选择先限定现有类型的投影/等值过滤；字段、NULL/int8 和确定性排序必须冻结。继续拒绝未支持的源删除/schema演进、Continuous、任意 SQL/多表 JOIN、跨数据集图、公开写入、跨机器托管 writer。公开写入及跨机器源 fencing 是后续独立切片。

## 3. 各切片验收合同

### A0：把实际支持与测试负载冻结下来

本次落地范围：

- [能力清单 v1](../../api/capabilities/v1.json)及schema覆盖12域，两个OpenAPI引用同一源码合同；dataset describe仍只提供schema/model/read_context/retention，不把它当全局能力协商。
- M0 functional/performance-smoke/stability-component接入不可覆盖v2原始归档。新运行先停止容器、采集日志和摘要，再删除容器；缺件/摘要损坏/采集失败拒绝归档。旧 `4de2fde7` 的result/trace/现存日志按原身份保全；14份旧容器日志不可恢复，不能宣称历史日志齐全。
- [synthetic合同](../design/a0-workload-contract.md)冻结seed17/16维、初始256行、每批16行及原查询；BM25/L2/RRF/训练manifest采用独立源输入真值，保留原始请求/响应。60秒窗口8次更新，四个四分位均要求读、append和publish，增长至384行；这是新负载版本，不与旧两次append当同负载比较。
- JSON持久向量键固定字符串，使归档数据集摘要可重算；旧整数键摘要不一致的归档保留原字节，新证据绑定新commit。10000行/32批及128 run上限、查询延迟/RSS/recall门槛未放宽。
- 当前没有业务数据集；媒体负载为0，OS缓存未受控，远端GET/HEAD、native完整峰值RSS、协调器训练I/O、五次受控重复及独立Parquet逐值真值仍缺。A0完成仅指上述有界合同与证据设施，不能推导完整M2、跨机或release通过。

以下保留原验收要求；其中未测成本须由后续切片补齐，不能从状态文字推定已有证据：

- 首个有限实现提交将M0 driver接入已有原始证据归档，保存当前仍在artifacts的结果/trace/容器日志并核对原commit/digest；新运行生成新证据，不把旧证据改绑新commit。覆盖缺件/损坏/同结果不同trace/重复运行；在保全完成前不清理当前artifacts。
- 对账功能/架构/接口/格式文档和实际 schema/服务发现：M0 SQL 与 M1/M2 job 分开、v1/v2 BM25 分开、源增量与索引全重建分开、内部 Lance 与外部连接器分开。API 导航的旧“无服务”文字不能作为新支持声明。
- 固定一个允许使用的数据清单及可复现 synthetic 对照，记录 seed、维度/距离、文本/媒体大小、重复/空值、过滤选择性、倾斜、append 频率和查询/训练并发。synthetic 仅为组件输入，不冒充业务 baseline。
- 先在现有10000行/32文件等预算内测量；登记硬件、对象后端、依赖锁、缓存定义、GET/HEAD/字节、协调器/worker RSS、构建及历史存储放大。超过当前向量维度或格式白名单的真实需求另立兼容切片。
- 提交前冻结结果真值、recall门槛及延迟/内存/请求预算。无现成预算先建立候选测量，经独立复核再定目标；不把首次自比较当作回归证据。
- 完整P0 driver为全文/RRF/训练建立独立真值，不能仅调用被测search/samples_for互证；安排贯穿全窗口的更新与刷新节奏，记录增长曲线。当前两次append后持续读的60秒测试继续只标本地短时集成。

### A1：让训练样本选择成为可用能力

进入条件：复用A0冻结的全视图输入、ID/version/split和预算作为对照；先补独立PyArrow读取实际导出Parquet的逐值真值，再扩展选择语义。A0只独立核验训练manifest，不替代此义务。

- 最小 API 在固定 view 上表达现有类型的等值过滤与列投影，先拒绝 JOIN、聚合、UDF 和任意 SQL。共用服务端选择语义，客户端仅转发；将来接 SQL 也走同一合同。
- manifest 记录选择规则/版本、实际 view、样本身份/record_version、投影 schema、seed/split、媒体与模型来源；空集合、NULL、int8无损传输、非法字段和超预算行为明确。
- 独立 PyArrow/关系真值比对样本集合、字段和 split；单 worker/三 worker/HTTP/CLI/MCP 同结果。已接受任务遭遇新发布、撤权、GC、取消或服务重启时，不漂移、不泄露、不留下无主 pin。
- 同负载记录选择前后扫描/导出量和RSS；不得用减少样本数与旧全量导出直接比较来声称执行器提速。通过后才更新 F05/F10 支持范围。

### A2：去掉协调器全量 rows 和全产物逐请求读取

进入条件：先冻结版本化描述符、不可变对象身份/摘要、缓存与pin/GC合同；在相同A0输入和质量门槛下补齐总RSS、真实I/O及缓存状态证据，然后才讨论扩大上限。

- 先定义版本化视图描述符：schema/model、逻辑分片集合、不可变对象身份/摘要、索引版本、记录映射及统计。协调器只传任务描述，worker 只读本片并按需回表；阶段性可保留 Python 控制面。
- 校验从“每请求全读”演进为有明确可信边界的产物准入/缓存校验和读取验证；持久层和本地缓存损坏/替换必须检测，认证与撤权不因缓存而省略。依赖闭包、pin 和 retiring 排他保持。
- 检索归并只接收有界候选；扫描/训练按批次或分片文件清单输出，避免协调器聚合全样本/整份 Parquet。总预算包含协调器、worker、native子进程、网络及临时产物；偏斜/慢片/缺片/取消失败明确。
- 独立单节点真值比较 ID/version/排序/RRF/Graph/训练样本覆盖；记录各进程内存曲线、真实读量、重复校验成本和冷/热表现。不得只改10000行等常量；提升上限必须附前后证据和独立复核。
- 持久协议升级前备份，声明旧reader/writer、历史v1/v2、在途任务和pin支持窗口；提供新目录重建/回滚路径。去掉重复Tantivy/全局ANN产物须证明旧视图/rebuild/恢复仍成立。

### A3：长期运行的历史、幂等与容量边界

进入条件：先设计history/operation保留、tombstone及未知提交对账，再构造合法跨128 run的独立场景；保留32批/10000行writer保护，不能以提高常量代替生命周期验证。

- 设计 runs/jobs/history 和 operation 指纹的保留期限、归档/tombstone、容量告警和受控清理；不删除尚需对账、被pin或当前发布引用的记录。
- 在跨128 run的独立场景验证构建→发布→retire/GC，重放旧operation不得产生新提交或倒退发布；用重建/多数据集等合法输入触发目录生命周期，不能绕过writer的32批限制。
- writer 的32批/10000行边界单独说明：本阶段可继续明确拒绝；若业务要求突破，则另做源快照/数据文件维护、稳定键和reader兼容切片，不能顺手放宽。
- 源提交前后断连/进程死亡、PG故障、响应丢失、旧generation、未知结果与pin竞争实际注入。跨机源提交仍不开放；本地flock和目录CAS分开验收。

### A4：用质量与成本报告收口 M2

- ANN：精确L2真值，低probe与全probe分别报告；选择性过滤、偏斜、同分、小片fallback、重建/重排及新版本移除记录后的映射逐项验证。内部Lance删除/compaction另做隔离POC，不修改已发布索引，也不表示开放Iceberg源delete语义。固定recall门槛后才比较速度。
- BM25：保留独立公式/全局统计/过滤/稳定排序；量测文档级JSON扫描和重复产物成本，再决定保持有界实现或替换访问结构。评分/分析器变更必须版本化，不扩大中文等未测声明。
- Graph：先验收现有一跳关系真值和全局扇出/内存/deadline；跨数据集节点语义、多跳与邻接优化不混入本片。
- 增量/写入：对独立PyIceberg reader比较版本与行；旧data GET为零不等于总I/O为零，要计HEAD、旧副本复制、全索引重建及历史保留放大。与查询/训练并发，验证共同发布、未知提交和旧视图可用性。
- 每类负载至少5次独立测量；真冷、热、部分命中、超过总缓存分别标明。无权限控制OS/远端缓存或无足够容量时记录缺失，不能标完整M2性能退出通过。只在实际driver、原始测量及比较器具备后推进相应门禁状态。
- 按受影响不变量补逐场景seed、注入/恢复trace；M2当前四项组件checks不能代替完整fault registry。完整12场景及verify-stability、长稳的ready转换仍按M3/M4实际证据推进，不因本片增加测量而直接改绿。

### A5/A6：跨机前先证明传输、任务和资源合同

- A5只读POC冻结一个固定view，至少三台独立目标主机、各自数据/索引分片与远端对象I/O；不能依赖共享绝对路径，也不能只放开loopback校验。
- 实现受保护传输、短期任务权限/密钥轮换、对象访问范围、owner/generation、deadline/取消与总请求/字节/内存预算。测试慢片/丢片/重复任务/网络分区/撤权；迟到结果不能发布。
- 在同数据/质量预算下比较单节点与多机的总成本和协调器趋势；记录Ballista扩展序列化、依赖版本、任务恢复是否适配。无收益或复杂度不可接受时保持有界部署，不以worker数作为通过标准。
- A6沿原路线图验收完整并发P0和coordinator恢复；公开写API、源catalog fencing、容量再平衡按所宣称范围分别完成。写提交未知先对账；只读查询可明确失败重试，不承诺透明恢复。

## 4. 暂缓项与生产发布队列

本阶段暂缓新湖格式、PG wire 后续 TLS/系统目录/更多驱动、内建OCR/ASR/embedding、复杂图语言、通用分布式JOIN/聚合、更多ANN算法及大规模Rust重写；若实际首批负载证明它们必要，先更新范围/依赖与ADR。

当前实现更新：PG 客户端接入已按 [ADR 0014](../decisions/0014-bounded-pg-wire.md) 实现并合入 main（`0702991`）的本机、非 TLS、只读、autocommit PG wire 首片，真实 psql 18/Psycopg 3.2.10 已有组件证据；当前支持边界见 [运行指南](../design/pg-wire-running.md)及[源码能力清单](../../api/capabilities/v1.json)。这不追溯扩大 A0 的验收范围，不表示远程 TLS、目录、事务或所有 SDK 已支持。

M4仍独立排队：完整performance/stability/soak、PG HA/PITR、对象/目录/pin联合恢复与撤权补偿、RPO/RTO、升级/回滚、审计/监控告警、镜像SBOM/许可证与发布环境。远端CI可在获准推送后尽早核验，阻断对外发布，但不阻断本地A0–A4开发；外部主机/服务/发布动作按实际授权执行。本计划不授权推送或部署。

## 5. 每片交付与本次文档任务

每片启动独立task，冻结基点、支持/拒绝、性能预算和故障断言；先局部真值再按plan运行功能/语言/组件性能/故障门禁。高风险的描述符、发布、GC、保留或门禁变更做独立复核；不通过删测试、改阈值、扩大缓存或缩小数据来消除回归。提交后对原始base检查并task-finish，归档原始测量与trace。两次无新证据失败时停止盲试、定位根因。

原文档任务 `capability-architecture-review` 只完成评审、状态校正与本计划。其起点 `4de2fde7faf04b640ae8dbe02022e78e94db59ee`；恢复点 `checkpoints/20261018T100510Z-before-capability-architecture-review-d8d5d2aa`。后续A0由独立切片和 `a0-main-integration` 完成，主线基点 `d95d1ada607fe40a6b1cf8eb19773b3a10f95bae`；报告覆盖该基点以来的全部A0变更。A1–A6未实施，无生产数据迁移，未推送或部署。

## 5. 测试补强前置要求

按新的用户要求，先执行[覆盖率变更计划](../design/test-coverage-change-plan.md)：对全部 Python modules/clients 与 Rust 生产源测量单元测试行覆盖率，目标为适用源码行严格100%，Rust按ADR0015逐行审查排除并保留原始值，未达到时明确失败并逐文件列缺口。HTTP与Psycopg SQL使用同一M0场景及PG18真值，包含参数/空值/完整int8/拒绝/撤权；M1/M2检索、Graph、训练仍按现有HTTP场景验收，不虚构SQL入口。覆盖率不替代A4质量、成本和故障验收，也不将完整performance/stability/soak改为ready。最新结果见[实现与测试复审](../reviews/2026-10-18-implementation-and-tests.md)。
