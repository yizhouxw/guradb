# 变更计划：标题

状态：进行中 / 已验证 / 尚缺证据。范围：填写模块与目标。

Git：起始 commit/分支、checkpoint、已有用户改动、任务 worktree；完成时填写最终 commit 与验证报告。阻断恢复采用哪个 checkpoint、哪些数据/外部副作用须另外对账。

## 需求、上下文与非目标

关联用户要求、ADR、接口和实际工作负载。记录本次不解决的内容，避免无关重构。

用户可观察的验收案例、里程碑、支持/拒绝白名单；task label/objective，独立真值/失败复现和预先冻结的资源预算。

## 风险与不变量

列出 plan 的 affected_modules / required_suites / invariants；解释版本、删除、发布、GC、权限、资源预算和兼容影响。

## 实现步骤与恢复点

列出可审查切片、已完成内容、下一步及中断后恢复信息。影响持久格式时写升级/回滚限制。

持久变更注明旧 reader/writer、进行中作业/pin、备份点、未知提交对账、兼容窗口及不可逆副作用。失败记录当前假设、已有证据、下一步；两次无新证据失败后定位根因，不盲目重跑。

## 验证合同

功能基线、负例、数据与 seed；性能环境/缓存/质量/成本和预算；故障注入点/恢复断言。无关项写具体原因，不填空泛“全部通过”。

## 结果与审查

记录实际命令、checkout digest、报告/日志位置、独立审查发现、未解决失败与限制。文档/模拟测试不得冒充运行时验证。

完成时核对验收案例、对应 suites、独立复核、文档/兼容说明、最终 commit/checkpoint 与原始 base 一致；证据归档位置及交接事项明确，未满足则保持未完成。
