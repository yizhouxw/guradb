# 用户文档场景与验证记录

在实现行为前填写合同，新增用户文档标记“规划/待实现”；实际执行后补证据。不可用预期输出冒充运行结果。

| 字段 | 本次填写 |
| --- | --- |
| 场景 ID / 用户目标 | 稳定 ID，用户希望观察什么 |
| 手册位置 | docs/user 下页面及章节；无行为影响时解释依据 |
| 文档先行证据 | 实现前文档 diff/任务记录路径，或先行提交 SHA |
| 支持与拒绝范围 | 输入/规模/类型/格式版本/身份及明确非目标 |
| 前置条件 | 工具版本、合成 fixture、服务/端口、配置和凭据注入方式 |
| 操作与成功断言 | 实际用户命令/API、独立真值、结果/版本/截断标志 |
| 失败断言 | 不支持输入、无权限、超限、未知结果、取消/恢复（按适用填写） |
| 兼容与迁移 | 默认值、旧 reader/writer、pin、升级/回退与不可逆副作用 |
| 验证入口 | 正向/负向测试路径与命令；性能/故障预算，不适用则说明原因 |
| 实测结果 | 执行后填写：passed/failed/missing、报告和脱敏 trace |
| 代码绑定 | commit、checkout digest、依赖/数据/配置摘要 |
| 复核与缺口 | 文档/行为一致性、时序、复核发现和剩余限制 |

完成前逐项核对文档命令的前置、执行结果和负例。链接检查仅证明可达；源码白名单、真实服务和最终报告各自提供不同证据。仍缺证据的场景不得标成已验证。
