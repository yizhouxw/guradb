# 目标任务卡

复制到共享根 `tasks/<id>/TASK.md`；这是模板，不授执行权。先查重，已有卡继续使用。正文保持一屏当前状态，原始报告/长历史放附件；未知必需条件写具体阻塞，不用null代表无限授权。

## 目标与边界（PM或该职责的目标owner填写一次）

- task_id / DRI稳定member_id / 授权来源：
- 用户或消费者可观察结果、验收案例、成功/拒绝边界：
- 阶段（核心链路/强化/发布/纯治理）、资源模型与数据流的关键断言、本次未测边界：
- 范围与非目标、输入合同/必要依赖：
- 总时间/资源预算、截止与停止条件；单轮限制沿用哪些现有策略：
- reviewer/消费者：技术验收用system-test或具名非作者；纯协作治理由PM文档检查与单独自审：

## 执行与当前状态（DRI维护）

- revision / checked_at / 当前状态 / 当前执行实例与写者：
- B / 当前候选H或NOT_CREATED / 分支 / worktree / receipt / checkpoint：
- 下一动作；真实阻塞的事实、影响、建议及需要谁决定；只填必要交付检查点：
- 已用预算/重试次数；验证/审查结论、限制与证据链接：

开发负责人在下面按需附子任务表，填实例/贡献身份、输入、唯一文件域/共享资源、输出及验证，不另复制一套项目计划。包内技术拆解、普通文件分配、自测修复、调用已授权独验与集成无需PM逐项签收。子任务执行包见[模板](execution-brief.md)。

## 按风险附加，已有证据只链接

- 运行或并行：唯一写域/资源窗口、适用suite及命令预算/累计次数、取消/清理责任、原失败/恢复点。
- 技术审查：完整贡献集合（含旧成员和修复者）、集合外reviewer、同一候选的发现→修复→确认；不能通过换会话洗掉作者。
- 接口/持久化/公开行为：用户手册先行、ADR/变更计划、兼容/迁移/恢复、真实依赖与module/pair/system/release层级。
- 交付：实际命令/报告、PR及原始B/审阅H/合入前M/合并G、精确main报告；未产生明确写NOT_CREATED，远端未知写UNKNOWN。
- 交接：旧writer停止、新writer签收、现场/证据可取性；状态字段不代替task-status/finish/abandon。

失败或缺失不得PASS，治理不得修改产品门禁；普通Git/hook/质量义务见[开发流程](../development-workflow.md)。跨目标/预算/权限/质量变化才升级，不能逐命令询问PM。项目暂停时只执行用户明确的例外范围，旧预算不续用。
